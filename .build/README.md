# Сборка выпусков

Скрипты собирают и упаковывают готовое в zip. Запускать их можно откуда
угодно — путь они берут от себя. Подробности про окружение и статические
сборки Qt — в `BUILD.md` в корне репозитория.

| Скрипт | Цель | Что получается |
|---|---|---|
| `build-win-i386.bat` | Windows XP+, 32 бита, Qt 5.6.3 + MinGW 4.9.2 | `ecat-<версия>-windows-i386-<рендерер>.zip` |
| `build-win-7.bat` | Windows 7+, 32 бита, Qt 5.15.2 + MinGW 8.1 | `ecat-<версия>-windows_7-i386-<рендерер>.zip` |
| `build-win-mingw-latest.bat` | Windows 10+, 64 бита, Qt 6 + MinGW 13 | `ecat-<версия>-windows-x86_64-<рендерер>.zip` |
| `build-win-msvc-latest.bat` | Windows 10+, 64 бита, Qt 6 + MSVC | `ecat-<версия>-windows-x86_64-msvc-<рендерер>.zip` |
| `build-linux.sh` | Linux x86_64, AppImage | `ecat-<версия>-linux-x86_64-<рендерер>.AppImage` |
| `build-macos.sh` | macOS, универсальный бинарник | `ecat-<версия>-macos-universal-<рендерер>.dmg` |
| `build-wasm.cmd`, `build-wasm.sh` | браузер | `ecat-<версия>-web.zip` и каталог рядом |

Каждый скрипт собирает все свои рендереры (`QT`, `OPENGL`, `SDL2` — набор
свой у каждой цели) и делает по архиву на рендерер. Аргумент `clean`
предварительно удаляет build-директории.

### Дополнительные аргументы современных целей

Действуют у `build-win-mingw-latest.bat`, `build-win-msvc-latest.bat`,
`build-linux.sh` и `build-macos.sh`; порядок аргументов любой. Старые киты
(XP и Windows 7) их не знают — эти возможности требуют C++17.

| Аргумент | Что делает |
|---|---|
| `mcp` | Собирает с MCP-сервером (`-DENABLE_MCP=ON`), к имени архива добавляется `-mcp`. Оконный вариант поддерживается только на `OPENGL`, остальные рендереры пропускаются с сообщением, а не с ошибкой. См. `MCP.md` |
| `headless` | Дополнительно собирает консольный вариант без графического интерфейса (`-DENABLE_GUI=OFF -DENABLE_HEADLESS=ON`). Только у Windows-скриптов: получается обычный zip с `ecat3-headless.exe`, которому не нужны ни Qt, ни его плагины |

Без этих аргументов выход скриптов ровно такой же, как раньше.

Консольный вариант под Linux и macOS собирается руками — упаковывать
консольную программу в AppImage или .dmg смысла мало:

```
cmake -S src -B build-headless -G Ninja -DCMAKE_BUILD_TYPE=Release       -DENABLE_GUI=OFF -DENABLE_HEADLESS=ON
```

Qt при `ENABLE_GUI=OFF` не ищется вовсе, так что эта сборка проходит и на
машине, где Qt не установлен.

Версия берётся из файла `VERSION` в корне репозитория — это единственное
место, где её надо править. Оттуда же её читает `project()` в
`src/CMakeLists.txt` и сборка для браузера, так что разойтись они не могут.
Сгенерированный `src/globals.h` содержит то же число, но он появляется только
после запуска cmake, поэтому скрипты на него не смотрят.

## Что куда кладётся

```
.build/build/windows_x86_64_mingw_QT/       промежуточная сборка
.build/release/ecat-3.6.0-windows-x86_64-QT/  готовое к упаковке
.build/release/ecat-3.6.0-windows-x86_64-QT.zip  выпуск
```

Оба каталога — `build/` и `release/` — в git не входят.

В выпуск кладётся исполняемый файл, содержимое `deploy/` (конфигурации
машин, ПЗУ, программы) и нужные библиотеки. `deploy/ecat.ini` — рабочий
файл разработчика, в выпуск он не попадает: настройки по умолчанию лежат в
`deploy/.ecat.ini` и переименовываются при упаковке.

Со статической сборкой Qt библиотек рядом с exe не остаётся вовсе.
Windows-скрипты определяют её сами: если каталог из `_QT_PREFIX_STATIC`
существует, берётся он, иначе выводится предупреждение и собирается
динамический вариант с Qt*.dll и рантаймом MinGW рядом.

## Пути к цепочкам

Пути прописаны в отдельных файлах — если у вас всё лежит иначе, править
надо только их:

| Файл | Что описывает |
|---|---|
| `vars-mingw-qt5.6.cmd` | Qt 5.6.3 + `mingw492_32` — цепочка Windows XP |
| `vars-mingw-qt5.15.cmd` | Qt 5.15.2 + `mingw810_32` — цепочка Windows 7 |
| `vars-mingw-latest.cmd` | Qt 6 + `mingw1310_64` |
| `vars-msvc-latest.cmd` | Qt 6 + переносимый MSVC из `C:\DEV\MSVC\msvc` |
| `vars-emsdk.cmd` | `C:\DEV\emsdk` — Emscripten для браузера |

CMake и Ninja во всех случаях берутся из поставки Qt (`Tools\CMake_64`,
`Tools\Ninja`).

## Общее для Windows-скриптов

`win-common.cmd` — общие подпрограммы: поиск 7-Zip, чтение версии,
пересоздание каталога, копирование `deploy/`, упаковка, отчёт о содержимом
и сброс build-директории, настроенной под другой генератор. Новую логику
выпуска надо класть туда, а не размножать по скриптам.

`win-build-qt5.cmd` — общее тело двух i386-сборок на Qt 5; сами
`build-win-i386.bat` и `build-win-7.bat` только выбирают цепочку и метку
платформы.

## Браузер

`build-wasm.sh` (и `build-wasm.cmd` под Windows) собирает **не выпуск, а
пакет для выкладки**: каталог со статикой, который кладётся в корень сайта
как есть, плюс тот же каталог в zip.

```
.build/release/ecat-3.6.0-web/
    index.html  ecat_wasm.js        страница
    ecat3.js  ecat3.wasm            сам эмулятор
    machines.json                   список машин для меню
    bundles/<машина>.bundle         ПЗУ, конфиг и образы дисков одной машины
    bundles/data.bundle             знакогенераторы и раскладки
    README.md  LICENSE.TXT  COPYRIGHT.TXT  nginx.conf.example
```

Наборы машин собирает `src/wasm/package_machines.py` из каталога `deploy/`:
по файлу на машину в подкаталоге `bundles/`, и страница тянет только тот,
который выбрали. Добавить машину можно, не трогая ни страницу, ни скрипт
сборки — достаточно положить `.cfg` с ПЗУ в `deploy/computers/`.

Нужен Emscripten; пути к нему — в `vars-emsdk.cmd`, а под Unix достаточно
`source emsdk_env.sh` перед запуском. Python и node берутся из самого emsdk.

**Раздавать это надо сервером, и с двумя заголовками:** эмулятор собран с
потоками, а `SharedArrayBuffer` доступен только на изолированном
происхождении. Без `Cross-Origin-Opener-Policy: same-origin` и
`Cross-Origin-Embedder-Policy: require-corp` страница молча встанет на
инициализации модуля. Настройка nginx с пояснениями лежит прямо в пакете —
`nginx.conf.example`; исходники обоих файлов пакета — в `.build/web/`.

Для пробы на своей машине: `python src/wasm/serve_wasm.py <каталог> 8080` —
обычный `python -m http.server` не годится, он этих заголовков не ставит.

## Языковые файлы

`update_translations.bat [build-директория]` запускает цель
`update_translations`. Без аргумента берётся значение по умолчанию из
самого файла; каталог должен быть тем, что настроен в конфигурации проекта.
