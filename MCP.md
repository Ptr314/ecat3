# Внешнее управление эмулятором: MCP-сервер

`eCat3 --mcp` превращает эмулятор в MCP-сервер (Model Context Protocol): он разговаривает
по JSON-RPC 2.0 через stdin/stdout, а клиент — например Claude Code — держит **живую сессию**.
Машина загружается один раз, дальше идут десятки обращений к состоянию устройств, нажатий
клавиш, шагов процессора и снимков экрана без перезапуска.

Это не новый язык управления. Внешний драйвер говорит **тем же словарём `.ecat`**, что и
сценарии (см. `SCRIPTING.md`): строка разбирается тем же парсером и попадает в тот же буфер
команд, который исполняет тот же `tick()`. Отсюда следует приятное: живая сессия — это по
сути сценарий, и всё, что работает в `.ecat`, работает и здесь.

## Сборка

Сервер собирается только по ключу, без него ни один его файл не компилируется:

```
cmake -S src -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DRENDERER_OPENGL=1 -DENABLE_MCP=ON
cmake --build build
```

Ограничение: **`ENABLE_MCP` вместе с GUI требует `RENDERER_OPENGL`**, иначе конфигурация
падает с `FATAL_ERROR`. Сборка без ключа на `--mcp` отвечает сообщением в stderr и кодом
возврата 2 — она не зависает и не показывает модальных окон.

## Подключение к Claude Code

В корне репозитория лежит `.mcp.json`. Путь к исполняемому файлу, рабочий каталог и каталоги
с библиотеками берутся из переменных окружения, значения по умолчанию рассчитаны на сборку
в дереве проекта:

```json
{
  "mcpServers": {
    "ecat3": {
      "command": "${ECAT3_EXE:-C:\\...\\eCat3\\src\\cmake-build-mcp\\eCat3.exe}",
      "args": ["--mcp", "--workdir", "${ECAT3_DEPLOY:-C:\\...\\eCat3\\deploy}"],
      "env": {
        "PATH": "${ECAT3_QT_BIN:-...\\Qt\\6.11.2\\mingw_64\\bin};${ECAT3_MINGW_BIN:-...\\Qt\\Tools\\mingw1310_64\\bin};${PATH}"
      }
    }
  }
}
```

- `ECAT3_EXE` — путь к собранному с ключом `eCat3`. **Абсолютный**: Windows разрешает
  относительную команду от рабочего каталога родительского процесса, а не от `cwd`,
  который задан дочернему, так что относительный путь просто не запустится.
- `ECAT3_DEPLOY` — рабочий каталог, тот, где лежат `computers/`, `software/` и `data/`.
  Его выставляет аргумент `--workdir`, потому что прокидывать рабочий каталог через
  конфигурацию MCP-клиента ненадёжно.
- `ECAT3_QT_BIN`, `ECAT3_MINGW_BIN` — нужны только динамической сборке: без них процесс
  не найдёт `Qt6*.dll` и рантайм mingw. Консольной сборке (`eCat3-headless.exe`) Qt не
  нужен вовсе, и это самый простой вариант, если с библиотеками возникли сложности.

Файл читается при старте сессии, и клиент спрашивает разрешение на сервер из репозитория;
проверить состояние можно командой `/mcp`. Пересобранный эмулятор подхватывается тоже
только новой сессией: запущенный сервер продолжает работать с тем кодом, с которым стартовал.

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `ecat_machine` | `config` | Грузит машину и запускает её. Вызывается первым; окно появляется именно здесь. Возвращает список устройств |
| `ecat_run` | `commands`, `timeout_ms` | Выполняет одну или несколько строк `.ecat` по порядку и возвращает весь их вывод. Основной инструмент |
| `ecat_screenshot` | `wait_ms` | Снимает экран и возвращает **картинкой** (PNG в теле ответа), а не путём к файлу |
| `ecat_status` | — | Состояние движка и, главное, **двигаются ли эмулированные часы** |
| `ecat_devices` | — | Имя, тип и класс каждого устройства загруженной машины |
| `ecat_describe` | `device` | Поля и команды одного устройства, чтобы не угадывать имена |
| `ecat_cancel` | — | Бросает то, чего машина уже не дождётся, и чистит очередь |

Отдельного инструмента для пошагового исполнения нет и не нужно: процессор уже отдаёт всё
через обычные команды —

```
COMMAND cpu.stop()
COMMAND cpu.step()
LOG cpu.pc
LOG cpu.registers
COMMAND cpu.breakpoint($100)
COMMAND cpu.run()
```

## Что стоит знать

**Задержки считаются в эмулированном времени.** Если процессор остановлен (`COMMAND cpu.stop()`,
`HLT`, зависшая машина), часы стоят, и `WAIT` не закончится никогда. Сервер это распознаёт:
вместо молчаливого зависания приходит `[stalled]` с указанием состояния движка. Команды, которым
эмулированное время не нужно (`LOG`, `COMMAND`, `PRINT`, `RESET`), при остановленном процессоре
выполняются — на этом и держится пошаговая отладка.

**Пачка команд в одном `ecat_run` — это один срез.** Все строки отправляются в
движок разом, и `tick()` прогоняет мгновенные команды пачки не выходя из своего
цикла, то есть на одном и том же значении часов. Поэтому два соседних `LOG`
показывают согласованное состояние, а не машину, успевшую уехать между ними:
это ровно та же семантика, что у тех же строк в файле сценария. Между
**разными** вызовами `ecat_run` машина, разумеется, продолжает идти в реальном
времени — если нужен именно срез, шлите чтения одной пачкой.

**Очередь строго упорядочена.** Брошенная по таймауту команда загораживает всё, что за ней;
про это приходит `[blocked]` с советом вызвать `ecat_cancel`. Отмена сбрасывает и невыполненный
хвост пачки.

**Вывод привязывается к своей команде.** Если строки всё-таки приходят от предыдущей, брошенной
команды, они помечаются `[from an earlier command]`, а не выбрасываются: обычно это именно та
диагностика, которая нужна.

**`SCREEN "-"`** — обычная команда `.ecat`, означающая «снимок только в память, файл не писать».
Она работает и в сборке без MCP, просто забрать байты там некому.

**Сессия накапливает состояние.** Машина, которую полчаса тыкали, — это не свежая загрузка.
Там, где важен порядок инициализации, ПЗУ или тайминги контроллера при сбросе, честнее
перезагрузить машину через `ecat_machine`.

**Рабочее дерево не пачкается.** В режиме `--mcp` `ecat.ini` не перезаписывается, в отличие от
обычного ручного запуска.

**Панель записи действий выключена.** Буфером команд владеет внешний драйвер, и нажатие
«Перемотать» в интерфейсе рвало бы ему очередь.

## Протокол

Транспорт stdio у MCP — по одному объекту JSON на строку, без заголовков `Content-Length`.
В stdout не попадает ничего, кроме протокола: диагностика идёт в stderr, туда же по ключу
`--mcp-trace` печатается вся переписка (удобно при ручном запуске из терминала).

Реализованы `initialize`, `notifications/initialized`, `tools/list`, `tools/call` и `ping`;
конец файла на stdin означает, что клиент ушёл, и эмулятор завершается.

Разбор и сборка JSON — `src/libs/picojson/picojson.h` (BSD-2). Сам сервер живёт в `src/mcp/`
и Qt не использует; единственный Qt-файл — `src/mcp_bridge.cpp`, он переносит смену машины
в поток интерфейса, потому что та пересобирает список устройств, меню и панели.
