# Общие замечания

* Сценарий &ndash; текстовый файл в кодировке UTF-8 с расширением __.ecat__.
* Одна строка &ndash; одна команда.
* Все задержки указываются в __миллисекундах эмулируемого времени__. Отсчет
  ведется по тактам процессора, а не по системным часам, поэтому один и тот же
  сценарий отрабатывает одинаково независимо от загрузки компьютера, на котором
  запущен эмулятор. Побочный эффект: если процессор остановлен (например, из
  отладчика), сценарий тоже стоит.
* Ошибки времени выполнения (нет устройства, не открылся файл, неизвестное
  свойство) записываются в лог, но __не прерывают__ сценарий. Строки, которые не
  удалось разобрать, пропускаются, а сообщения о них выводятся в лог при старте.
* Движок сценариев находится в Qt-независимом ядре эмулятора
  (`src/emulator/script/`), поэтому доступен в том числе в сборке для браузера.

# Командная строка

~~~
ecat3 [опции] [файл]

  -c, --config <file.cfg>     Конфигурация машины. Отменяет выбор машины,
                              сохраненный в ini-файле (раздел [Startup], ключ
                              default).
  -s, --script <file.ecat>    Сценарий для выполнения.
  -h, --help                  Справка.
  -v, --version               Версия.
~~~

Позиционный аргумент распознается по расширению: __.cfg__ трактуется как
конфигурация, __.ecat__ &ndash; как сценарий. Это позволяет перетаскивать файл
сценария на исполняемый файл эмулятора.

Пути к __.cfg__ разрешаются так же, как значение __default__ в ini-файле:
абсолютный путь используется как есть, иначе поиск идет относительно текущего
каталога, а затем относительно каталога __computers__.

Порядок выбора конфигурации:

1. Значение ключа __--config__, если он указан;
2. Иначе &ndash; аргумент команды [MACHINE](#machine) из сценария, если она есть;
3. Иначе &ndash; машина, сохраненная в ini-файле.

# Формат файла сценария

~~~
# Комментарий
// Тоже комментарий

КОМАНДА аргумент1, аргумент2
КОМАНДА устройство.свойство(параметры)
~~~

* Пустые строки и комментарии (__#__ и __//__) игнорируются. Внутри строк в
  кавычках символы комментариев обрабатываются как обычный текст.
* Имена команд регистронезависимы.
* Аргументы разделяются запятыми. Запятая внутри двойных кавычек разделителем не
  является.
* Строковые аргументы заключаются в двойные кавычки; кавычки при разборе
  снимаются.
* Числа записываются так же, как в файлах конфигурации (см. [CONFIG.md](CONFIG.md)):
    * без префикса &ndash; десятичное;
    * __$__ &ndash; шестнадцатеричное (например, __$F000__);
    * __&amp;__ &ndash; восьмеричное (например, __&amp;177714__). В этой записи принято
      писать адреса и коды машин на К1801ВМ1, и в ней же их печатает
      [LOG](#log) при основании 8;
    * __#__ &ndash; двоичное (например, __#1010__);
    * __\___ &ndash; десятичное (например, __\_3000__);
    * суффикс __k__ умножает значение на 1024.
* Число без префикса десятичное, если машина не объявила другую систему
  счисления, см. [RADIX](#radix).
* Относительные имена файлов ищутся сначала рядом со сценарием, затем в каталоге
  конфигурации машины, в подкаталоге __files__, в каталоге __software__ и в
  каталоге __data__.
* Записываемые файлы (снимок экрана, `tape.save`, `fdd.save`, `ram.save`) с
  относительным именем кладутся рядом со сценарием. Так все, что сценарий
  оставляет после себя, собирается в одном месте.

# Команды

### MACHINE
~~~
MACHINE "Файл .cfg"
~~~
Задает конфигурацию, которая будет загружена перед выполнением сценария. Должна
быть первой командой в файле. Игнорируется, если конфигурация указана в командной
строке ключом __--config__.

Путь по умолчанию задается относительно каталога __computers__, как в ini-файле,
но может быть и абсолютным.

### WAIT
~~~
WAIT n
~~~
Задержка на __n__ миллисекунд эмулируемого времени.

### KEY
~~~
KEY n1, n2, клавиша1, клавиша2, ...
~~~
Имитация нажатия клавиш.

* __n1__ &ndash; задержка перед нажатием каждой клавиши, мс;
* __n2__ &ndash; время удержания каждой клавиши, мс.

Клавиши перечисляются по именам из таблицы раскладок (см. раздел
[scan-keyboard](CONFIG.md#scan-keyboard) в CONFIG.md): __0..9__, __A..Z__,
__f1..f12__, __space__, __ret__, __esc__, __back__, __tab__, __left__, __up__,
__right__, __down__, __home__, __end__, __ins__, __del__, __shift__, __ctrl__,
__caps__ и знаки препинания. Имена регистронезависимы. Неизвестное имя
записывается в лог как ошибка, остальные клавиши отрабатываются.

Имя можно указать с приставкой __shift+__ &ndash; тогда клавиша нажимается при
удерживаемом Shift. Это нужно для символов, которые есть на машине только в
верхнем регистре.

~~~
KEY 50,50,F,1
KEY 100,50,ret
KEY 50,50,shift+2
~~~

Имя, которое иначе сломало бы строку, заключается в кавычки: __","__ для
запятой, __"\\""__ для кавычки, __"\\\\"__ для обратной косой черты.

### KEYDOWN, KEYUP
~~~
KEYDOWN клавиша
KEYUP клавиша
~~~
Нажимает или отпускает одну клавишу и сразу продолжает сценарий. В отличие от
[KEY](#key), клавиша остается нажатой, пока не встретится __KEYUP__: так
записываются аккорды и удержание модификаторов. Именно эти команды порождает
[запись действий](#Запись-действий-из-интерфейса), когда нажатия
перекрываются. Все, что сценарий еще держит нажатым к моменту остановки,
отпускается автоматически.

~~~
KEYDOWN shift
KEY 100,100,"\""
KEYUP shift
~~~

Вместо клавиши хоста можно назвать клавишу самой машины &ndash; так, как ее
называет нативная таблица клавиш и рисунок клавиатуры (см.
[Экранная клавиатура](CONFIG.md#экранная-клавиатура)). Такие имена начинаются с
`key_`, ни одно имя клавиши хоста с него не начинается, поэтому пути не
пересекаются. Нативный путь не проходит через перекладку ЙЦУКЕН &rarr; ЯВЕРТЬ и
позволяет выразить то, чего в хостовой таблице нет: на БК защелка нижнего
регистра меняет код той же клавиши.

~~~
KEYDOWN key_str            // защелка СТР
KEYUP key_str
KEYDOWN key_1              // придет $21, а не $31
KEYUP key_1
~~~

Именно эти команды записываются при нажатии клавиш мышью в окне экранной
клавиатуры, поэтому такая запись воспроизводится один в один.

### TYPE
~~~
TYPE "текст" [, n1, n2]
~~~
Набирает строку текста клавишами. Удобно для ввода команд монитора и листингов
Бейсика. __n1__ и __n2__ имеют тот же смысл, что и в [KEY](#key); по умолчанию
&ndash; 50 мс.

Поддерживаются экранированные последовательности: __\n__ &ndash; ввод (Return),
__\t__ &ndash; табуляция, __\\\\__ &ndash; обратная косая черта, __\\"__ &ndash;
кавычка.

Символы, которые на данной машине набираются только с Shift (кавычка, скобки,
знаки препинания верхнего регистра), нажимаются вместе с Shift автоматически:
раскладку спрашивают у самой клавиатуры, поэтому одна и та же строка работает
на машинах с разными раскладками.

~~~
TYPE "10 PRINT \"HELLO\"\n"
TYPE "RUN\n", 30, 30
~~~

### SCREEN
~~~
SCREEN ["Имя файла"]
~~~
Сохраняет снимок экрана в файл формата PNG. Относительное имя трактуется
относительно каталога сценария. Если имя не указано, используется
__screen-ГГГГ-ММ-ДД-ЧЧ-ММ-СС.png__.

Снимок делается потоком отрисовки, и сценарий дожидается записи файла, поэтому
команду [EXIT](#exit) можно ставить сразу после SCREEN.

Имя __"-"__ означает «только в память, файла не писать». Это нужно внешнему
драйверу, который забирает готовый PNG прямо из эмулятора
(`Emulator::take_screenshot_png()`), см. [MCP.md](MCP.md); в обычном сценарии
такой снимок просто некому забрать.

### RADIX
~~~
RADIX n
~~~
Задает систему счисления (2, 8, 10 или 16), в которой сценарий пишет числа
без префикса.

Обычно эту команду писать не нужно: [MACHINE](#machine) берет значение из
параметра __radix__ загруженной конфигурации (см.
[CONFIG.md](CONFIG.md#system)). У машин БК он равен 8, поэтому сразу после
загрузки машины можно писать так, как написано в документации на нее:

~~~
COMMAND ram0.set16(024004, 012737, 000377, 177714)   // MOV #377,@#177714
LOG ram0.value16(024004, 024011)
WAITFOR cpu.pc == 024232, _5000
~~~

Правило одно: в объявленной системе счисления читается __любое__ число без
префикса. Величины, которые принадлежат сценарию, а не машине &ndash; задержки
и удержания в [WAIT](#wait), [KEY](#key), [TYPE](#type), таймауты, аргументы
[LOGDEFS](#logdefs), код возврата [EXIT](#exit) &ndash; пишутся с префиксом
__\___:

~~~
WAIT _3000                  // три эмулируемые секунды
KEY _100,_100,ret           // задержка и удержание в миллисекундах
LOGDEFS _16,_8              // слово, восьмеричный вывод
~~~

Имена клавиш числами не считаются: `KEY _100,_100,2,2,2` трижды нажимает
клавишу __2__.

Явный префикс сильнее радикса: `$A5` останется шестнадцатеричным.

Загрузка машины устанавливает радикс заново, поэтому RADIX ставится после
[MACHINE](#machine), а не до нее.

### LOGDEFS
~~~
LOGDEFS n1, n2
~~~
Устанавливает умолчания для вывода числовых значений командой [LOG](#log).

* __n1__: 8 или 16 &ndash; разрядность выводимых значений (байт, слово);
* __n2__: 2, 8, 10 или 16 &ndash; основание системы счисления.

Если команда не встречалась, значения выводятся как байты в шестнадцатеричном
виде. Префиксы вывода соответствуют формату чисел в конфигурации: __$__ для
шестнадцатеричных, __#__ для двоичных, __&__ для восьмеричных; десятичные
выводятся без префикса.

Свойства, которые заведомо шире байта (счетчик команд, частота, позиция на ленте
и т.&nbsp;п.), выводятся в своей разрядности и командой LOGDEFS не обрезаются.

### LOG
~~~
LOG устройство.свойство
LOG устройство.свойство(n1)
LOG устройство.свойство(n1, n2)
~~~
Записывает в лог значение свойства устройства. Параметры задают диапазон адресов
или индексов внутри свойства: если параметров нет, используется диапазон
__{0, 0}__, если один &ndash; __{n1, n1}__.

Формат строки:

~~~
[устройство.свойство] значение
[устройство.свойство] начальный_адрес: значение значение ...
~~~

Вторая форма используется для устройств с адресуемым размером больше одного,
например для блоков памяти.

~~~
LOG any_port.value
LOG ram.value($F000,$F00F)
LOG cpu.registers
~~~

Список свойств см. в разделе [Свойства устройств](#Свойства-устройств).

### COMMAND
~~~
COMMAND устройство.команда
COMMAND устройство.команда(параметры)
~~~
Выполняет действие с устройством.

~~~
COMMAND fdd0.load("image.dsk")
COMMAND tape.play
COMMAND ram0.set($F000, $C3)
~~~

Список команд см. в разделе [Команды устройств](#Команды-устройств).

### WAITFOR
~~~
WAITFOR устройство.свойство[(диапазон)] оператор значение [, таймаут]
~~~
Приостанавливает сценарий, пока числовое свойство устройства не примет нужное
значение. Это надежнее слепой задержки: сценарий не сломается на другой машине
или при изменении времени загрузки.

* Операторы: __==__, __!=__ (синоним __<>__), __<__, __<=__, __>__, __>=__;
* __таймаут__ &ndash; максимальное время ожидания в миллисекундах, по умолчанию
  10000. По истечении таймаута в лог пишется сообщение, и сценарий продолжается.

Свойство опрашивается раз в миллисекунду эмулируемого времени.

~~~
WAITFOR fdc.busy == 0, 5000
WAITFOR fdd0.loaded == 1
~~~

### RESET
~~~
RESET [cold|soft]
~~~
Сброс машины. По умолчанию &ndash; холодный.

### LOAD
~~~
LOAD "Имя файла"
~~~
Загружает файл средствами эмулятора, как это делает пункт меню
&laquo;Открыть&raquo;. Тип определяется по расширению (.rk, .rko, .ord, .bru,
.hex, .bin, .cim и др.).

Для загрузки образа в конкретное устройство используйте
[COMMAND](#command) &mdash; например, `COMMAND fdd0.load(...)`.

### PRINT
~~~
PRINT "текст"
~~~
Записывает произвольную строку в лог. Удобно для разделения разделов вывода.

### LOGFILE
~~~
LOGFILE "имя"
~~~
Переопределяет базовое имя лог-файла. Имеет смысл только до первой записи в лог.

### EXIT
~~~
EXIT [код]
~~~
Завершает работу эмулятора. Код становится кодом возврата процесса (если не указан — ноль),
одинаково в оконной и консольной сборке: на это смотрит проверочный набор и любой другой
внешний запуск. При воспроизведении из интерфейса код не используется.

# Запись действий из интерфейса

Действия пользователя можно записать в сценарий прямо из главного окна и
воспроизвести их. Кнопки собраны в правой части панели инструментов и
продублированы в меню __&laquo;Эмуляция / Запись действий&raquo;__ (блок кнопок
скрывается флажком __&laquo;Настройки / Панель записи&raquo;__, настройка хранится в
ini-файле):

| Кнопка | Действие |
|---|---|
| Открыть запись | Загружает файл __.ecat__ в буфер, указатель ставится на начало. Если буфер не пуст, сначала предлагается сохранить его |
| Сохранить запись | Записывает буфер в файл. Недоступна, пока буфер пуст |
| Начать запись / Пауза | Начинает запись событий; повторное нажатие приостанавливает ее |
| Воспроизвести / Пауза | Запускает буфер с текущего указателя (с начала, если он в конце); повторное нажатие приостанавливает |
| В начало | Ставит указатель на начало буфера |
| Стоп | Останавливает запись или воспроизведение, указатель остается на месте |

Правила записи:

* В пустой буфер первой строкой попадает [MACHINE](#machine) с текущей
  конфигурацией, так что файл можно запустить и из командной строки. При
  воспроизведении буфера, записанного для другой машины, эта машина
  загружается автоматически.
* Записываются нажатия клавиш, сброс, переключение параметров устройств из
  выпадающих списков панели (например, тип вывода дисплея), операции с
  образами дисков, снимки экрана и управление магнитофоном. Все они
  превращаются в обычные команды сценария: [KEY](#key),
  [KEYDOWN, KEYUP](#keydown-keyup), [RESET](#reset), [COMMAND](#command),
  [SCREEN](#screen).
* Время между событиями считается по тактам процессора и записывается как
  [WAIT](#wait). Пауза записи тоже попадает в буфер как __WAIT__ перед
  следующим событием.
* Одиночное нажатие превращается в одну строку __KEY__ с задержкой и
  временем удержания; перекрывающиеся нажатия (Shift вокруг символа, аккорд в
  игре) &ndash; в __KEYDOWN__ / __KEYUP__.
* Имена файлов в снимках экрана и образах записываются полными путями, при
  воспроизведении файлы перезаписываются без вопросов.
* Если воспроизведение остановлено посередине и нажата запись, хвост буфера
  от указателя отбрасывается и запись продолжается с этого места.
* Команда [EXIT](#exit) при воспроизведении из интерфейса только завершает
  сценарий, окно не закрывается.

В строке состояния слева от регулятора громкости показывается положение:
__мин:сек / мин:сек__ при воспроизведении (указатель и длительность буфера) и
общая длительность при записи. Длительность считается по командам __WAIT__,
__KEY__ и __TYPE__; время, которое занимают [WAITFOR](#waitfor) и
[SCREEN](#screen), в нее не входит.

# Лог-файл

При получении первой команды, выводящей что-либо в лог ([LOG](#log),
[PRINT](#print) или сообщение об ошибке), в каталоге сценария создается файл

~~~
имя_скрипта-ГГГГ-ММ-ДД-ЧЧ-мм-СС.log
~~~

Создание файла отложенное: сценарий без вывода не оставляет за собой файлов.
Каждая строка сразу сбрасывается на диск, поэтому лог сохраняется даже при
аварийном завершении.

# Свойства устройств

Свойства ниже доступны команде [LOG](#log) и условию [WAITFOR](#waitfor).

## Общие для всех устройств

| Свойство | Описание |
|---|---|
| __name__ | Имя устройства |
| __type__ | Тип устройства |
| __class__ | Класс устройства (_fdd_, _tape_, _generic_device_) |
| __interfaces__ | Значения всех интерфейсов устройства. Основной инструмент отладки соединений между устройствами |

## Адресуемые устройства

Доступны для __ram__, __rom__, __port__, __port-address__, __ram-address__,
__memory-mapper__, __page-mapper__, __i8255__, __i8253__, __i8259__, __i8251__,
__i8257__, __i8275__, __wd1793__, __gmd70__ и контроллеров Агат.

| Свойство | Описание |
|---|---|
| __value__ | Значение или диапазон значений. Чтение производится без побочных эффектов &mdash; так же, как это делает окно дампа памяти |
| __value16__ | Тот же диапазон, прочитанный словами (16 разрядов, младший байт первый) &mdash; так, как его видит процессор с 16-разрядной шиной |
| __size__ | Адресуемый размер устройства |

Для устройств размером 1 (портов, регистров) диапазон игнорируется и выводится
одно значение без адреса. Для остальных выводится начальный адрес и значения
через пробел.

~~~
LOG port-videomode.value
LOG ram0.value($F000,$F00F)
LOG port-user.value(0,3)        // все четыре регистра i8255
LOG ram0.value16(&024000, &024013)  // тот же участок словами, как его видит К1801ВМ1
~~~

# Команды устройств

## Общие для всех устройств

| Команда | Параметры | Описание |
|---|---|---|
| __reset__ | [cold\|soft] | Сброс устройства |
| __option__ | id, значение | Установка параметра устройства (те же параметры, что и в выпадающих списках панели инструментов) |

## Адресуемые устройства

| Команда | Параметры | Описание |
|---|---|---|
| __set__ | адрес, значение [, значение...] | Запись байтов подряд, начиная с адреса |
| __set16__ | адрес, значение [, значение...] | То же словами (16 разрядов, младший байт первый). Адрес должен быть четным |
| __fill__ | от, до, значение | Заполнение диапазона значением |

Несколько значений в одной команде пишутся по возрастающим адресам, поэтому
фрагмент машинного кода занимает строку на команду, а не строку на байт.
Ничего не записывается, пока не проверен весь список: при ошибке в любом
значении команда сообщает его номер и память остается нетронутой.

~~~
COMMAND ram0.set($F000, $C3, $00, $F8)                  // JP $F800 на i8080
COMMAND ram0.set16(&024004, &012737, &000377, &177714)   // MOV #377,@#177714 на К1801ВМ1
~~~

# Примеры

## Снимок экрана после загрузки

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000
SCREEN "boot.png"
EXIT
~~~

## Загрузка образа и запуск программы

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000

COMMAND fdd0.load("Disk2.ODI")
WAITFOR fdd0.loaded == 1

TYPE "F1\n"
WAIT 3000

SCREEN "loaded.png"
EXIT
~~~

## Отладочный дамп состояния

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000

LOGDEFS 8,16
PRINT "=== Процессор ==="
LOG cpu.registers
LOG cpu.flags

PRINT "=== Карта памяти ==="
LOG mapper.map

PRINT "=== Порты ==="
LOG port-videomode.value
LOG port-page.value
LOG port-keyboard.interfaces

PRINT "=== Начало ОЗУ ==="
LOG ram0.value($0000,$003F)
EXIT
~~~

Готовый пример находится в файле __deploy/scripts/demo.ecat__.

Набор сценариев по всем машинам эмулятора вместе с эталонными результатами и
раннером лежит в каталоге __tests__ (см. [tests/README.md](tests/README.md));
это же и самый большой набор рабочих примеров.

# Развитие

Система спроектирована с расчетом на два направления:

* __Запись и воспроизведение сценариев из интерфейса эмулятора__ &ndash;
  реализовано, см. [Запись действий из интерфейса](#Запись-действий-из-интерфейса).
  Движок (`ScriptEngine`) не привязан к файлу: он выполняет список команд,
  который собирается и во время работы (`ScriptRecorder`). Команда разбирается
  функцией `parse_script_line()`, записывается обратно
  `format_script_command()`, а выполняется `ScriptEngine::execute()`.
* __Внешнее управление эмулятором (MCP-сервер)__ &ndash; реализовано, см.
  [MCP.md](MCP.md). Наружу вынесены перечисление устройств, их самоописание
  (`get_device_fields()`, `get_device_commands()`), структурированное чтение
  свойств (`get_field()` возвращает данные, а не только готовую строку) и
  выполнение команд (`send_command()` возвращает `emulator::Result`). Файл
  сценария при этом не обязателен: внешний драйвер добавляет команды в тот же
  буфер через `ScriptEngine::submit()` и ждет их завершения по `get_done_pc()`,
  а движок в интерактивном режиме не заканчивает работу на последней команде,
  а паркуется до следующей.
