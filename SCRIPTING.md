# Общие замечания

* Сценарий &ndash; текстовый файл в кодировке UTF-8 с расширением __.ecat__.
* Одна строка &ndash; одна команда.
* Все задержки указываются в __миллисекундах эмулируемого времени__. Отсчет
  ведется по тактам процессора, а не по системным часам, поэтому один и тот же
  сценарий отрабатывает одинаково независимо от загрузки компьютера, на котором
  запущен эмулятор. Побочный эффект: если процессор остановлен (например, из
  отладчика), сценарий тоже стоит.
* Ошибки времени выполнения (нет устройства, не открылся файл, неизвестное
  свойство) записываются в лог, но __не прерывают__ сценарий. Строки, которые не
  удалось разобрать, пропускаются, а сообщения о них выводятся в лог при старте.
* Движок сценариев находится в Qt-независимом ядре эмулятора
  (`src/emulator/script/`), поэтому доступен в том числе в сборке для браузера.

# Командная строка

~~~
ecat3 [опции] [файл]

  -c, --config <file.cfg>     Конфигурация машины. Отменяет выбор машины,
                              сохраненный в ini-файле (раздел [Startup], ключ
                              default).
  -s, --script <file.ecat>    Сценарий для выполнения.
  -h, --help                  Справка.
  -v, --version               Версия.
~~~

Позиционный аргумент распознается по расширению: __.cfg__ трактуется как
конфигурация, __.ecat__ &ndash; как сценарий. Это позволяет перетаскивать файл
сценария на исполняемый файл эмулятора.

Пути к __.cfg__ разрешаются так же, как значение __default__ в ini-файле:
абсолютный путь используется как есть, иначе поиск идет относительно текущего
каталога, а затем относительно каталога __computers__.

Порядок выбора конфигурации:

1. Значение ключа __--config__, если он указан;
2. Иначе &ndash; аргумент команды [MACHINE](#machine) из сценария, если она есть;
3. Иначе &ndash; машина, сохраненная в ini-файле.

# Формат файла сценария

~~~
# Комментарий
// Тоже комментарий

КОМАНДА аргумент1, аргумент2
КОМАНДА устройство.свойство(параметры)
~~~

* Пустые строки и комментарии (__#__ и __//__) игнорируются. Внутри строк в
  кавычках символы комментариев обрабатываются как обычный текст.
* Имена команд регистронезависимы.
* Аргументы разделяются запятыми. Запятая внутри двойных кавычек разделителем не
  является.
* Строковые аргументы заключаются в двойные кавычки; кавычки при разборе
  снимаются.
* Числа записываются так же, как в файлах конфигурации (см. [CONFIG.md](CONFIG.md)):
    * без префикса &ndash; десятичное;
    * __$__ &ndash; шестнадцатеричное (например, __$F000__);
    * __#__ &ndash; двоичное (например, __#1010__);
    * суффикс __k__ умножает значение на 1024.
* Относительные имена файлов ищутся сначала рядом со сценарием, затем в каталоге
  конфигурации машины, в подкаталоге __files__, в каталоге __software__ и в
  каталоге __data__.

# Команды

### MACHINE
~~~
MACHINE "Файл .cfg"
~~~
Задает конфигурацию, которая будет загружена перед выполнением сценария. Должна
быть первой командой в файле. Игнорируется, если конфигурация указана в командной
строке ключом __--config__.

Путь по умолчанию задается относительно каталога __computers__, как в ini-файле,
но может быть и абсолютным.

### WAIT
~~~
WAIT n
~~~
Задержка на __n__ миллисекунд эмулируемого времени.

### KEY
~~~
KEY n1, n2, клавиша1, клавиша2, ...
~~~
Имитация нажатия клавиш.

* __n1__ &ndash; задержка перед нажатием каждой клавиши, мс;
* __n2__ &ndash; время удержания каждой клавиши, мс.

Клавиши перечисляются по именам из таблицы раскладок (см. раздел
[scan-keyboard](CONFIG.md#scan-keyboard) в CONFIG.md): __0..9__, __A..Z__,
__f1..f12__, __space__, __ret__, __esc__, __back__, __tab__, __left__, __up__,
__right__, __down__, __home__, __end__, __ins__, __del__, __shift__, __ctrl__,
__caps__ и знаки препинания. Имена регистронезависимы. Неизвестное имя
записывается в лог как ошибка, остальные клавиши отрабатываются.

~~~
KEY 50,50,F,1
KEY 100,50,ret
~~~

### TYPE
~~~
TYPE "текст" [, n1, n2]
~~~
Набирает строку текста клавишами. Удобно для ввода команд монитора и листингов
Бейсика. __n1__ и __n2__ имеют тот же смысл, что и в [KEY](#key); по умолчанию
&ndash; 50 мс.

Поддерживаются экранированные последовательности: __\n__ &ndash; ввод (Return),
__\t__ &ndash; табуляция, __\\\\__ &ndash; обратная косая черта.

~~~
TYPE "10 PRINT \"HELLO\"\n"
TYPE "RUN\n", 30, 30
~~~

### SCREEN
~~~
SCREEN ["Имя файла"]
~~~
Сохраняет снимок экрана в файл формата PNG. Относительное имя трактуется
относительно каталога сценария. Если имя не указано, используется
__screen-ГГГГ-ММ-ДД-ЧЧ-ММ-СС.png__.

Снимок делается потоком отрисовки, и сценарий дожидается записи файла, поэтому
команду [EXIT](#exit) можно ставить сразу после SCREEN.

### LOGDEFS
~~~
LOGDEFS n1, n2
~~~
Устанавливает умолчания для вывода числовых значений командой [LOG](#log).

* __n1__: 8 или 16 &ndash; разрядность выводимых значений (байт, слово);
* __n2__: 2, 8, 10 или 16 &ndash; основание системы счисления.

Если команда не встречалась, значения выводятся как байты в шестнадцатеричном
виде. Префиксы вывода соответствуют формату чисел в конфигурации: __$__ для
шестнадцатеричных, __#__ для двоичных, __&__ для восьмеричных; десятичные
выводятся без префикса.

Свойства, которые заведомо шире байта (счетчик команд, частота, позиция на ленте
и т.&nbsp;п.), выводятся в своей разрядности и командой LOGDEFS не обрезаются.

### LOG
~~~
LOG устройство.свойство
LOG устройство.свойство(n1)
LOG устройство.свойство(n1, n2)
~~~
Записывает в лог значение свойства устройства. Параметры задают диапазон адресов
или индексов внутри свойства: если параметров нет, используется диапазон
__{0, 0}__, если один &ndash; __{n1, n1}__.

Формат строки:

~~~
[устройство.свойство] значение
[устройство.свойство] начальный_адрес: значение значение ...
~~~

Вторая форма используется для устройств с адресуемым размером больше одного,
например для блоков памяти.

~~~
LOG any_port.value
LOG ram.value($F000,$F00F)
LOG cpu.registers
~~~

Список свойств см. в разделе [Свойства устройств](#Свойства-устройств).

### COMMAND
~~~
COMMAND устройство.команда
COMMAND устройство.команда(параметры)
~~~
Выполняет действие с устройством.

~~~
COMMAND fdd0.load("image.dsk")
COMMAND tape.play
COMMAND ram0.set($F000, $C3)
~~~

Список команд см. в разделе [Команды устройств](#Команды-устройств).

### WAITFOR
~~~
WAITFOR устройство.свойство[(диапазон)] оператор значение [, таймаут]
~~~
Приостанавливает сценарий, пока числовое свойство устройства не примет нужное
значение. Это надежнее слепой задержки: сценарий не сломается на другой машине
или при изменении времени загрузки.

* Операторы: __==__, __!=__ (синоним __<>__), __<__, __<=__, __>__, __>=__;
* __таймаут__ &ndash; максимальное время ожидания в миллисекундах, по умолчанию
  10000. По истечении таймаута в лог пишется сообщение, и сценарий продолжается.

Свойство опрашивается раз в миллисекунду эмулируемого времени.

~~~
WAITFOR fdc.busy == 0, 5000
WAITFOR fdd0.loaded == 1
~~~

### RESET
~~~
RESET [cold|soft]
~~~
Сброс машины. По умолчанию &ndash; холодный.

### LOAD
~~~
LOAD "Имя файла"
~~~
Загружает файл средствами эмулятора, как это делает пункт меню
&laquo;Открыть&raquo;. Тип определяется по расширению (.rk, .rko, .ord, .bru,
.hex, .bin, .cim и др.).

Для загрузки образа в конкретное устройство используйте
[COMMAND](#command) &mdash; например, `COMMAND fdd0.load(...)`.

### PRINT
~~~
PRINT "текст"
~~~
Записывает произвольную строку в лог. Удобно для разделения разделов вывода.

### LOGFILE
~~~
LOGFILE "имя"
~~~
Переопределяет базовое имя лог-файла. Имеет смысл только до первой записи в лог.

### EXIT
~~~
EXIT [код]
~~~
Завершает работу эмулятора.

# Лог-файл

При получении первой команды, выводящей что-либо в лог ([LOG](#log),
[PRINT](#print) или сообщение об ошибке), в каталоге сценария создается файл

~~~
имя_скрипта-ГГГГ-ММ-ДД-ЧЧ-мм-СС.log
~~~

Создание файла отложенное: сценарий без вывода не оставляет за собой файлов.
Каждая строка сразу сбрасывается на диск, поэтому лог сохраняется даже при
аварийном завершении.

# Свойства устройств

Свойства ниже доступны команде [LOG](#log) и условию [WAITFOR](#waitfor).

## Общие для всех устройств

| Свойство | Описание |
|---|---|
| __name__ | Имя устройства |
| __type__ | Тип устройства |
| __class__ | Класс устройства (_fdd_, _tape_, _generic_device_) |
| __interfaces__ | Значения всех интерфейсов устройства. Основной инструмент отладки соединений между устройствами |

## Адресуемые устройства

Доступны для __ram__, __rom__, __port__, __port-address__, __ram-address__,
__memory-mapper__, __page-mapper__, __i8255__, __i8253__, __i8259__, __i8251__,
__i8257__, __i8275__, __wd1793__, __gmd70__ и контроллеров Агат.

| Свойство | Описание |
|---|---|
| __value__ | Значение или диапазон значений. Чтение производится без побочных эффектов &mdash; так же, как это делает окно дампа памяти |
| __size__ | Адресуемый размер устройства |

Для устройств размером 1 (портов, регистров) диапазон игнорируется и выводится
одно значение без адреса. Для остальных выводится начальный адрес и значения
через пробел.

~~~
LOG port-videomode.value
LOG ram0.value($F000,$F00F)
LOG port-user.value(0,3)        // все четыре регистра i8255
~~~

## Отдельные устройства

| Устройство | Свойства |
|---|---|
| __ram__, __rom__ | __fill__ &ndash; байт заполнения при холодном сбросе |
| __port__, __port-address__ | __default__ &ndash; значение после сброса, __mask__ &ndash; маска записи |
| __memory-mapper__ | __map__ &ndash; текущая карта памяти и портов, __config__ &ndash; значение регистра конфигурации |
| __register__ | __value__, __default__, __mask__ |
| __cpu__ (i8080, z80, 6502, 65c02, 1801vm1, 1801vm2) | __pc__, __command__, __registers__, __flags__, __clock__, __debug__ |
| __fdd__ | __loaded__, __file__, __protected__, __selected__, __motor__, __led__, __track__, __sector__, __side__, __position__ |
| __wd1793__ | __status__, __track__, __sector__, __data__, __busy__, __drive__ |
| __taperecorder__ | __mode__ (0 &ndash; стоп, 1 &ndash; воспроизведение), __position__, __total__, __size__, __baudrate__, __recording__, __recorded__ |
| __i8253__ | __counters__, __start__, __modes__, __outputs__, __gates__ |
| __i8259__ | __imr__, __irr__, __isr__, __initialized__ |
| __speaker__ | __volume__, __muted__ |
| __generator__ | __enabled__, __out__, __period__ |
| Дисплеи | __resolution__ &ndash; текущее разрешение экрана |

Свойство __map__ диспетчера памяти выводит записи в том порядке, в котором они
проверяются при обращении. Записи, отключенные механизмом __cancelinit__,
помечаются как __[off]__.

# Примеры

## Снимок экрана после загрузки

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000
SCREEN "boot.png"
EXIT
~~~

## Загрузка образа и запуск программы

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000

COMMAND fdd0.load("Disk2.ODI")
WAITFOR fdd0.loaded == 1

TYPE "F1\n"
WAIT 3000

SCREEN "loaded.png"
EXIT
~~~

## Отладочный дамп состояния

~~~
MACHINE "orion-128/Orion-128-m3.cfg"
WAIT 2000

LOGDEFS 8,16
PRINT "=== Процессор ==="
LOG cpu.registers
LOG cpu.flags

PRINT "=== Карта памяти ==="
LOG mapper.map

PRINT "=== Порты ==="
LOG port-videomode.value
LOG port-page.value
LOG port-keyboard.interfaces

PRINT "=== Начало ОЗУ ==="
LOG ram0.value($0000,$003F)
EXIT
~~~

Готовый пример находится в файле __deploy/scripts/demo.ecat__.

# Развитие

Система спроектирована с расчетом на два будущих направления:

* __Запись и воспроизведение сценариев из интерфейса эмулятора.__ Движок
  (`ScriptEngine`) не привязан к файлу: он выполняет список команд, который может
  быть собран и во время работы. Команда разбирается отдельной функцией
  `parse_script_line()`, а выполняется `ScriptEngine::execute()`.
* __Внешнее управление эмулятором (MCP-сервер).__ Наружу вынесены перечисление
  устройств, их самоописание (`get_device_fields()`, `get_device_commands()`),
  структурированное чтение свойств (`get_field()` возвращает данные, а не только
  готовую строку) и выполнение команд (`send_command()` возвращает
  `emulator::Result`). Файл сценария при этом не обязателен.
