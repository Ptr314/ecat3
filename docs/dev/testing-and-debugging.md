## Scripting

`src/emulator/script/` is a Qt-free script runner driving the emulator from a text file (`docs/SCRIPTING.md` has the full command reference, in Russian). Launch with `eCat3 --script <file.ecat>` (or `--config <file.cfg>`; a positional argument is dispatched by extension) from the `deploy/` working directory.

Scripts load a machine (`MACHINE`), wait, press keys (`KEY`, `TYPE`), take screenshots (`SCREEN`), dump device state to a log (`LOG dev.field`, `LOGDEFS` picks width and base), send device commands (`COMMAND dev.cmd(args)`), snapshot the whole machine (`SAVESTATE`, see `extensions-and-state.md`), and `EXIT`. This is the practical way to reproduce a bug or verify a machine without driving the GUI by hand.

Two things surprise people:
- **`WAIT` counts emulated time, not wall-clock.** If the config fails to load or the CPU is stopped, the clock never advances and the script hangs forever. Wrap batch runs in a timeout.
- **The log file is created lazily** next to the script, named `<script>-YYYY-MM-DD-HH-mm-SS.log`; a script that prints nothing leaves no file behind.
- **Relative paths in `COMMAND dev.load("...")` resolve from the script's directory first**, then the config's directory / `files/` / `deploy/software/<machine>`, then the working directory (`deploy/`). Test assets therefore live in `tests/files/` and are loaded as `"../files/x.dsk"` from `tests/scripts/`.
- **On the БК a `KEY` held for 200 ms already autorepeats** in the MK-DOS / ANDOS shells, so a cursor move lands one entry further than asked: hold keys for `_50`, and walk to a known position (several `up` to the top) instead of trusting where the cursor was left
- **`SCREEN` waits for a frame from the render thread**, so whatever follows it runs at an emulated moment that depends on the host. Take screenshots after the measurements, never between a `WAIT` and a timing-sensitive `COMMAND`. When a screenshot has to come in the middle (`slow-uknc-tsspd` turns TSSPD's pages with a key), stop **every** processor around it (`COMMAND cpu.stop()`, `ppu.stop()`, `SCREEN`, `ppu.run()`, `cpu.run()`): with all of them stopped `timer_proc()` moves every domain by the same amount, so their interleaving is kept. "Stopped" there is `CPU::frozen()` (execute() returns 0), not `m_debug`: a К1801ВМ1 held by `~dclo` spends cycles even when stopped, and counting it as stopped made time crawl in 8-clock steps instead of standing still. Stepping each stopped domain on its own (as it still does while any processor runs) shifted the УК-НЦ's two domains against each other by a host-dependent amount, and TSSPD's counts moved by one between runs
- **A command line script starts at the machine's first clock**: the frontend arms it (`Emulator::arm_script()`) before loading the machine, and `run()` starts it on the emulation thread after the reset, before the first slice; the frontend's `start_script()` afterwards only sets up its controls. Started after `load_config()`/`run()` returned, it began wherever the machine had got to meanwhile - nothing on an idle host, a few hundred instructions under `-j 8` - and every `WAIT`/`KEY` moved with it: TSSPD on the УК-НЦ counted differently in the windowed build under load, and 2 of 16 parallel headless copies of one boot diverged at their first `LOG`
- **Load a test machine with `MACHINE` from an `.ecat`, not through an `.ext`'s `@script`**: the embedded script starts after the machine has already run for a while, so its `WAIT`s end at different instructions from run to run (`work-poisk-*.ecat` load `tests/files/poisk-*.ext`)
- **`COMMAND dev.set` writes with `force`**: an i8255 port set this way is latched but not driven onto its lines. Drive a port from guest code when the wiring is what is being tested
- **`TYPE` cannot type every character on every machine**: a key that exists only with Shift in a Rus-mode map entry (`:` on Irisha) comes out wrong. Use `KEY 50,50,shift+colon` instead.

Devices expose themselves to scripts through `get_device_fields()` / `get_field()` (readable state) and `get_device_commands()` / `send_command()` (actions), declared in `ComputerDevice` and overridden down the hierarchy. `AddressableDevice` already provides `value`/`value16`/`size` plus `set`/`set16`/`fill` (`set` and `set16` take a list of values for consecutive addresses, so machine code is one line per instruction), and `CPU` provides `pc`/`registers`/`flags` plus `stop`/`run`/`step`/`breakpoint`/`setreg`, so a new device usually needs nothing to be scriptable.

## Regression suite

- Most behavior testing is via `.cfg` file modifications
- **Regression suite**: `python tests/run_tests.py` runs an `.ecat` script per machine and diffs the log, the screenshots and any file the script writes against `tests/expected/` (`--all` adds the slow tape/CPU tests, `-k <substr>` filters, `--update` re-records references, `-j N` parallelises). Emulated time makes every run byte-identical, so a screenshot is a valid reference. See `tests/README.md`; a machine or device change that alters behaviour means re-recording the affected references in the same commit
- **The same scripts through MCP**: `python tests/run_mcp_tests.py --exe <build with ENABLE_MCP>` (at max by default, a `SPEED` put in place of the script's first empty line - not `--speed` of the server, which would run the machine ahead between `ecat_machine` and `ecat_run`, and not a line of its own, which would shift the line numbers of error messages) replays every test (no development build enables MCP by default; `src/cmake-build-mcp` is a headless one configured with `-DENABLE_GUI=OFF -DENABLE_HEADLESS=ON -DENABLE_MCP=ON`) against `<exe> --mcp` (`ecat_machine` plus one `ecat_run`) and diffs the answer against the same `expected/*.txt`, which is the only check of the `ScriptSink` path. A live session runs the machine between loading it and the first command, so anything sampled from absolute emulated time (`ay.level`, a generator phase) will not repeat: such a script declares `# @nomcp <reason>` in its header and is skipped
- **Any stderr output fails every test**: the runner treats a non-empty stderr as a problem, so the core must not print diagnostics. Real discrepancies are listed per test in `tests/results/report.txt`. On Windows without `python` on PATH use `py tests/run_tests.py`
- **A machine without a sound card is such an stderr source**: the audio driver says so and keeps going. `eCat3-headless --no-sound` (`SystemData::audio_enabled`, checked in `GenericSound::load_config`) opens no audio device at all, and the runner passes it whenever the chosen exe is the headless one — which is also the only build it finds on a machine without Qt. `sound.active` reports whether audio is really open. The flip side: `--no-sound` returns from `GenericSound::load_config()` before `init_sound()`, so a headless-only run never enters the audio setup path at all — a fault there shows up only when the suite runs the windowed build
- **`--update -k X` re-records every artifact of X**, including screenshots that already passed within their `@pixels` tolerance (an animation phase): restore those with `git checkout` so only the intended reference changes
- **A failure under `-j 8` alone is a test reading the host's timing**: `boot-2cpu` (4 of 5 stressed runs) was the late script start (see `arm_script()` above), `state-unior` a `SCREEN` taken right after a snapshot loaded - the ВГ75 picture has its size only after a frame, and the `KEYDOWN` after the `SCREEN` landed at a host-dependent moment. Put a `WAIT` of a frame before such a `SCREEN` and stop the processors around it. `work-bk-0011m-screen` and `work-argo-zx` failed one run in two even alone, and the fault was in the device, not the test: a size or a mode the render thread applied when it came round (see "Emulation > Speed" below). `state-uknc-sound` was on the old list too and did not fail in 10 stressed runs; rerun a failure with `-k`, and if it then passes, look for what in the test or the start depends on the host
- **Keep test assets tiny**: every `"../results/…"` name in a script becomes a compared artifact, so do not save whole disk images from a test. Verify a write by reading it back on the machine (`DIR`, `TYPE`) plus a counter field such as `fdc.writes`. Synthetic images go in `tests/files/` next to the Python that generates them (an image shorter than the geometry is zero-padded on load)
- **Tests run on the shipped defaults, not on the developer's ini**: `apply_saved_device_options()` reads `[DeviceOptions]` from `deploy/ecat.ini`, where the GUI remembers a monochrome БК display or a plugged mouse, so `KeepIni` in `tests/run_tests.py` (also used by `run_mcp_tests.py`) swaps in a copy of `deploy/.ecat.ini` for the run and puts the developer's file back afterwards. A script started by hand still sees the developer's ini, which is why the mouse test plugs its socket explicitly
- **The runner prefers a windowed build over the headless one**: `tests/run_tests.py` scans
  `src/cmake-build-*/eCat3.exe` first and only falls back to `eCat3-headless`, and it prints the
  executable it picked. Rebuilding one directory and recording references with another silently bakes
  the old behaviour into `expected/`; pass `--exe` when in doubt
- **`deploy/ecat.ini` is not in git** (`.gitignore`): every run rewrites it, so it is the developer's own file. The distributed defaults are `deploy/.ecat.ini`, which the release scripts package as `ecat.ini`. A missing `ecat.ini` is made a copy of `.ecat.ini` by both frontends and by `tests/run_tests.py` - without its `[TapeFiles]` no tape image loads, which is how a fresh checkout would otherwise break every tape test. A new default setting therefore goes into `.ecat.ini`
- CPU tests: `src/tests/*.asm` and the `slow-*` scripts that run them (6502 functional test, zexall, Orion memory test)
- Debug configurations (`debug = 1` in the `system` section) are hidden from the machine chooser unless `show_debug_versions=1` in the ini, and `src/wasm/package_machines.py` keeps them and their ROMs out of the web build entirely

## Debugging

- **`LOG cpu.history(_40)` answers "how did it get here"** on the 1801 processors: the last 256 executed addresses, oldest first. Combined with `COMMAND cpu.breakpoint(addr)` at the crash address it finds a wild jump in one run; that is how the УК-НЦ plane index bug (176640 halved into a processor address, corrupting one word of a loaded program) was traced
- **A halted CPU still runs the script engine**: `Emulator::timer_proc()` calls `script->tick()` on the zero-cycle path too, so `LOG`, `COMMAND` and the other instant verbs work while `cpu.stop()` holds the processor. The delays cannot - they are counted in emulated time and that has stopped, which is what an MCP session reports as a stall instead of hanging forever.
- **`COMMAND sound.record("f.wav")` … `sound.record()` captures what goes to the audio device**, also under `--no-sound` (44100 Hz); the file lands next to the script. The window plays at the device's `sample_rate` (22050 by default), so a `--no-sound` recording can sound brighter than what the user hears: run the headless build without `--no-sound` to record at the real rate. numpy/matplotlib are not installed system-wide: make a venv in the scratchpad for spectrograms
- **A `.ecats` snapshot carries its own `@config`**: a fix to a machine's `.cfg` (a new device, a mapper line) does not reach a snapshot taken before it. To test a user's snapshot against the fix, patch the `@config` text inside a copy of the zip
- **To bisect a regression, build an old commit in a `git worktree`**: the submodule `src/libs/dsk_tools` comes up empty there, copy its contents in from the main tree before configuring (`ENABLE_GUI=OFF ENABLE_HEADLESS=ON`), and run it from the worktree's own `deploy/` after copying `.ecat.ini` to `ecat.ini`
- **Measuring the cost of a core change**: every build runs in real time and spins between slices, so wall time and process CPU time say nothing. Accumulate `steady_clock` time around `timer_proc()` in the emulation loop (a temporary insert, dumped to a file at exit), run the same fixed script twice before and after, and compare; the spread between two runs is about 5%. When comparing screenshots across runs at different CPU speeds, remember the program is at a different moment in each
- **No compile-time logging**: the old `LOGGER` / `LOG_*` macros and the `Logger` class are gone. To trace a device, expose its state through `get_device_fields()` / `get_field()` and read it from an `.ecat` script (`LOG dev.field`), like `bk-fdc` does with its `trace` field
- **PDF documents in `docs-external/`**: the Read tool cannot render them here (no poppler); `/mingw64/bin/pdftotext` from Git Bash or `pypdf` extracts the text layer
- **The address label of `LOG dev.value(from,to)` follows the LOGDEFS base**: after `LOGDEFS _8,_16` on a БК the label `$0740` is hex (octal 003500), not an octal address
- **Scripts beat GUI automation**: `LOG mapper.map` prints the memory and port map in the order ranges are matched (with `[off]` on ranges disabled by `cancelinit`) — usually the fastest way to see that a window or page is wired to the wrong device. `LOG cpu.registers`, `LOG ram0.value(from,to)` and `SCREEN` cover most of the rest
