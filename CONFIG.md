# Общие замечания

* Кодировка для всех файлов &ndash; UTF-8.
* Описание конфигураций компьютеров содержится в файлах с расширением __.cfg__. Файлы должны находиться в любом подкаталоге ниже каталога __computers__.
* Эмулятор обходит все подкаталоги __computers__ и собирает общий список доступных систем.
* Системные файлы, загружаемые из конфигурации, должны находиться в том же каталоге, что и .cfg.
* Файлы, загружаемые через интерфейс эмулятора, по умолчанию будут искаться в каталоге __software__.
* Текстовое описание конфигурации должно находиться в файле, имя которого совпадает с файлом конфигурации, но с расширением __.md__ в формате [Markdown](https://ru.wikipedia.org/wiki/Markdown).
* Файл cfg состоит из описаний устройств:
    * Первым устройством в файле должно быть устройство [__system__](#system), задающее общие параметры и описание системы.
    * Вторым устройством принято описывать [CPU](#cpu). Обязательно, чтобы в файле был процессор с именем __cpu__: его частота устанавливается как основная системная.
    * Далее идут описания остальных устройств и их конфигураций. Список допустимых устройств и их параметров см. далее.
    * Также обязательным является наличие устройства [memory-mapper](#memory-mapper) с именем __mapper__, задающее отображение остальных устройств на адресное пространство процессора.
    * Процессоров в машине может быть больше одного, см. [машины с несколькими процессорами](#машины-с-несколькими-процессорами).

# Синтаксис описания устройств

~~~
device_id: device_type {
    parameter1 = value
    parameter2 = value
    ~interface1 = other_device.interface3
    ~interface2[bits] = !other_device.interface4[bits]
}
~~~

* Устройства соединяются друг с другом с помощью интерфейсов.
* Набор интерфейсов специфичен для каждого типа устройств.
* Если ширина интерфейса у двух устройств различна, нужно указывать диапазон подключаемых битов.
* Обычные параметры задаются как ___имя = значение___. Имена параметров и форматы значений специфичны для каждого устройства.
    * Цифровые значения можно дополнять суффиксами:
        * k: значение будет умножено на 1024.
    * Или префиксами:
        * $: число будет рассматриваться как шестнадцатеричное.
        * &amp;: число будет рассматриваться как восьмеричное. Так принято записывать адреса и коды машин на К1801ВМ1 (БК), и в этой же записи их печатает [LOG](SCRIPTING.md#log).
        * #: число будет рассматриваться как двоичное.
        * \_: число будет рассматриваться как десятичное. Нужен в файлах, где объявлен __radix__ (см. [system](#system)): им помечаются величины, которые к машине не относятся &ndash; частоты, размеры, задержки.
* Соединения интерфейсов задаются в следующем формате:
    * __~address = cpu.address__
        * Простое соединение интерфейсов одинаковой ширины.
    * __~page = portFB.value[2-3]__
        * Биты [0-1] интерфейса __page__ подключаются к битам [2-3] интерфейса __value__ устройства __portFB__;
        * Ширина интерфейса берется из правой части.
    * Если в начале правой части стоит знак «!», интерфейсы будут соединены с инверсией.

## Пример

~~~
port-user : i8255 {}

latch : register {
	~in[0-3] = port-user.B[0-3]
	~c = port-user.CH[3]
}

romdisk : rom {
	size = 512k
	image = rom512.rom
	~address[0-7] = port-user.B
	~address[8-11] = port-user.CL
	~address[12-14] = port-user.CH[0-2]
	~address[15-18] = latch.out[0-3]
	~data = port-user.A
}
~~~
* К порту на основе i8255 подключается rom-диск размером 512 Кб. Номер выбранной страницы (размером 32 Кб) хранится в регистре-защелке, которая срабатывает на установку старшего бита адреса.

# Встроенные данные (base64)

Параметр, в котором указывается файл (__image__ у ПЗУ и дисковода, __map__, __keys__), может нести сами данные вместо ссылки на файл:

~~~
bios : rom {
	size = _22
	image = fill.rom {base64:
		BIDgAMAVAEDBFQAg
		whVVVZAQQn7/AQ==
	}
}
~~~

* Признак встроенных данных &ndash; блок `{base64: ...}` после имени. Имя остается обязательным: по его расширению устройство выбирает формат образа (`.dsk`, `.hfe`, `.hex` и т.д.).
* Данные могут занимать несколько строк; пробелы, табуляции и переводы строк внутри блока пропускаются.
* При загрузке машины данные раскодируются в файл во временном каталоге эмулятора (`ecat3-cache` в системном каталоге временных файлов), и устройство получает путь к нему. Файл пишется заново при каждой загрузке, так что изменения, внесенные машиной в такой образ дискеты, до следующей загрузки не доживают.
* Файлы, в которых таких блоков нет, читаются как раньше.
* Встроенные данные разрешены и в .cfg, и в [расширениях](#расширения-конфигураций-ext); для расширений это основной способ собрать демонстрацию в один файл.

# Расширения конфигураций (.ext)

Расширение &ndash; это вариант машины, записанный как список правок к ее базовой конфигурации. Сама база при этом не меняется: так делаются варианты, мало отличающиеся друг от друга, пользовательские конфигурации и демонстрационные пакеты с программой и начальным сценарием.

~~~
@extends bk/BK-0010-01.cfg
@version БК0010-01 с игрой
// комментарий
display:mode = mono
-mapper:@memory[177714-177715] = ay
mapper:@memory[177600-177601] = port-177700
fdd0:image = game.img
@script
WAIT _3000
TYPE "S160000"
KEY _100,_100,ret
~~~

## Директивы

* __@extends__ `<путь>` &ndash; базовая конфигурация, обязательна. Относительный путь считается от каталога __computers__, абсолютный берется как есть. База должна быть файлом .cfg: расширение расширения не допускается. Загрузка базы по URL пока не поддерживается.
* __@version__ `<название>` &ndash; название варианта, обязательно. Заменяет __version__ из раздела [system](#system): под этим названием вариант виден в списке машин.
* __@protected__ &ndash; необязательна: файл защищен от правки. В [редакторе](#редактор-расширений) кнопки «Редактировать» и «Удалить» для него недоступны, копирование разрешено, и копия защиту не наследует. Так помечены расширения, входящие в поставку. `@protected 0` &ndash; то же, что ее отсутствие.
* __@script__ &ndash; необязательна и завершает файл: все строки после нее &ndash; [сценарий](SCRIPTING.md), который выполняется после загрузки машины.
* Строки, начинающиеся с `//`, &ndash; комментарии. После директивы комментарий отделяется пробелом.

## Правки свойств

* `устройство:свойство = значение` &ndash; свойство записывается так же, как внутри описания устройства в .cfg, вместе с диапазонами и блоком `{...}`. Блок `{...}` может продолжаться на следующих строках.
* `-устройство:свойство` &ndash; удаление свойства из базы.
* `-устройство` &ndash; удаление устройства целиком. Всё, что на него ссылается (диапазоны диспетчера, связи интерфейсов, __mix__), нужно убрать или поправить теми же правками, иначе загрузка машины остановится на первой такой ссылке. Раздел __system__ удалить нельзя.
* Раздел __system__ правится так же: `system:order = 3`.
* Числа без префикса читаются в системе счисления базы (см. __radix__ в [system](#system)).
* Правки применяются по порядку, сверху вниз.

Свойство в базе опознается по __ключу__: имени вместе с префиксом (`~`, `@`) и левым диапазоном &ndash; `image`, `~data[0-7]`, `@memory[177714-177715]`.

* Если в базе есть строка с таким ключом, она заменяется на месте. Если нет &ndash; свойство добавляется в конец описания устройства.
* Если в базе то же свойство записано с другими модификаторами (`~data` при `~data[0-7]` в базе), загрузка прерывается с ошибкой: сначала удалите строку базы (`-port-ppi:~data[0-7]`), затем добавьте свою.
* Ключ в базе не всегда уникален: диспетчер может отдавать один диапазон нескольким устройствам, порт &ndash; собирать одно поле из двух источников. Замена такого свойства &ndash; ошибка. При удалении нужную строку выбирают значением: `-mapper:@memory[177714-177715] = ay`.
* Диапазоны диспетчера (`@memory`, `@port`, `@page`) &ndash; элементы списка: строка с тем же диапазоном и тем же устройством заменяется (так меняются ее параметры в `{...}`), любая другая добавляется в конец карты. Порядок строк в карте важен (см. [memory-mapper](#memory-mapper)): чтобы новый диапазон перекрыл старый, старый нужно удалить.
* Удаление строки, которой в базе нет, и правка несуществующего устройства &ndash; ошибка.

## Файлы расширения

* Файлы, на которые ссылается расширение, ищутся сначала рядом с ним, затем там же, где файлы базовой конфигурации.
* Описание для списка машин &ndash; файл .md с тем же именем рядом с расширением; если его нет, показывается описание базы.
* Опции устройств (цвет экрана, разъемы) запоминаются для варианта отдельно от базы.

## Упакованные расширения (.ext.zip)

Расширение вместе с образами можно упаковать в ZIP-архив с именем `имя.ext.zip`. В корне архива должен лежать ровно один файл .ext; остальные файлы архива &ndash; его образы, на которые он ссылается по имени. Архив распаковывается во временный каталог эмулятора (`ecat3-cache/ext/<имя>-<контрольная сумма>`), поддерживаются методы stored и deflate без шифрования и ZIP64. Эмулятор этот каталог не чистит: каждая новая версия архива оставляет в нем свою копию, и удалять их можно в любой момент, когда эмулятор не запущен.

## Где лежат расширения

* В каталоге __computers__ рядом с .cfg: такие расширения попадают в общий список машин, в семейство своей базы.
* В каталоге пользователя: __ecat-exts__ рядом с эмулятором в Windows, `~/ecat-exts` в Linux и macOS. Эти расширения тоже видны в списке машин; расширение пользователя, которое не загружается, показывается там серым в группе «Конфигурации с ошибками», а причина видна во всплывающей подсказке.
* Файл .cfg, .ext или .ext.zip можно открыть пунктом меню «Открыть файл...» или указать в командной строке: он загружается как машина, а не в память текущей.

## Редактор расширений

В окне выбора машины над списком &ndash; кнопки:

* __Копировать__ &ndash; новое расширение на основе выбранной машины: от .cfg &ndash; расширение этой базы, от .ext &ndash; копия его правок. К версии добавляется « (n)» с первым свободным номером.
* __Редактировать__ &ndash; только для .ext, кроме помеченных __@protected__.
* __Удалить__ &ndash; только для .ext и .ext.zip, после подтверждения, и тоже кроме __@protected__. Базовые .cfg не удаляются.
* Через разделитель &ndash; переключатель «Показывать отладочные конфигурации» и переключатель «Пользовательские конфигурации». Отжатый (по умолчанию) показывает машины из __computers__, нажатый &ndash; из каталога пользователя (__ecat-exts__). Копия, сохраненная в каталог пользователя, переключает список туда, чтобы ее было видно. Положение переключателя запоминается в ini-файле (`[Startup] show_user_configs`).

Упакованные расширения (.ext.zip) не копируются и не редактируются: обратно в архив редактор не пишет.

Редактор &ndash; таблица: база (не меняется), имя файла (заполняется при первом сохранении), версия, затем параметры устройств, которые они разрешают менять:

| Устройство | Параметр | Поле |
|---|---|---|
| fdd | __image__ | образ диска: выбор файла, очистка (пустой привод), «Вложить» |
| uknc-hdd | __image__ | образ винчестера: только ссылкой, без вложения &ndash; машина пишет в образ по ходу работы |
| dl11 | __port__ | имя последовательного порта компьютера |
| dl11 | __station__ | номер станции в сети, десятичный; только у линии, которой конфигурация задала номер (сетевой адаптер) |
| uknc-hdd | __volatile__ | куда идёт запись: в файл образа или только в память |
| rom | __image__ | образ ПЗУ; только у ПЗУ с параметром __files__ (кассеты картриджей) |
| connector | __default__ | что вставлено в разъем |
| bk-display | __mode__ | цветность экрана |
| uknc-display | __colors__ | цветность экрана |

* В файл пишутся только поля, значение которых отличается от базы. Правки, которых редактор не знает, и секция @script сохраняются как есть.
* Очищенный образ записывается удалением (`-fdd0:image`): привод без образа пуст, машина загружается.
* С отметкой «Вложить» файл записывается в расширение [встроенными данными](#встроенные-данные-base64). Без нее &ndash; ссылкой: относительной, если файл лежит рядом с расширением, иначе с полным путем.
* При первом сохранении эмулятор спрашивает, куда положить файл: рядом с базовым .cfg или в каталог пользователя. Имя &ndash; `<имя базы>-<n>.ext`.
* Под таблицей &ndash; текст [сценария расширения](#сценарий-расширения) (секция @script) в синтаксисе .ecat. Пустое поле &ndash; секции нет.
* Кнопка «Запустить» загружает расширение в эмулятор, как «OK» в окне выбора машины; несохраненные изменения перед этим предлагается сохранить. Встроенный сценарий при таком запуске выполняется.

Список полей устройство отдает методом `get_config_fields()` (см. `src/emulator/core.h`); новое поле добавляется там, без правки редактора.

## Сценарий расширения

* Выполняется после загрузки машины, если ничего другого машиной не управляет. Сценарий из командной строки (`--script`), воспроизведение записи и клиент MCP важнее: при них встроенный сценарий не запускается.
* Лог сценария создается рядом с файлом расширения, относительные пути в нем считаются оттуда же.
* Номера строк в сообщениях об ошибках &ndash; номера строк файла .ext.

# Устройства

## Общие параметры
Следующие параметры могут быть установлены всем устройствам:

~~~
dev: device {
    cold_reset = 1
    soft_reset = 1
    clock = 1/1
    clock_source = cpu
}
~~~

* __cold_reset__: Устройство будет инициализироваться при холодном сбросе.
* __soft_reset__: Устройство будет инициализироваться при теплом сбросе.
* __clock__: Тактовая частота устройства. Может указываться в долях от системной частоты в формате "множитель/делитель" (например, __1/2__ для половины системной частоты). По умолчанию &ndash; 1/1.
* __clock_source__: Имя процессора, от которого устройство тактуется. По умолчанию &ndash; __cpu__. Имеет смысл только в [машинах с несколькими процессорами](#машины-с-несколькими-процессорами): устройство попадает в тактовый домен указанного процессора, и доли в __clock__ отсчитываются от его частоты. От неё же берутся все величины, которые устройство пересчитывает из реального времени в такты &ndash; строка развёртки, скорость ленты, шаг звука.

Если не указано иное, оба значения для всех устройств по умолчанию установлены в 1.

## Специальные

### system
Основные параметры системы, раздел должен быть первым в файле.
~~~
system {
	type = orion-128
	name = Орион-128
	version = КР580ВМ80 / Монитор-3
	charmap= radio-86rk
	files = "Orion-128 (*.bru *.ord *.rko);;All files (*.*)"
	debug = 0
	order = 0
}
~~~

* __type*__: Идентификатор типа компьютера. Используется для сбора конфигураций в группы в диалоге выбора.
* __name*__: Эквивалент type, отображается в интерфейсе.
* __version__: Вариант исполнения. Выводится вторым уровнем в дереве выбора конфигурации.
* __order__: Место конфигурации внутри своей группы. Машины группы сортируются сначала по __order__, потом по алфавиту, а сами группы всегда стоят по алфавиту, независимо от него. По умолчанию 0, поэтому файл без этого параметра остается там же, где и был, а число опускает машину ниже остальных: у Ириши основные варианты помечены 10, а Диалог и Каспий &ndash; 20, и потому идут в конце. Число всегда десятичное, __radix__ на него не действует. Тот же порядок использует список машин веб-сборки.
* __charmap__: Файл с отображением кодировки на UTF-8. Должен состоять из 256 символов UTF-8, где номер символа &ndash; его код в исходном компьютере.
    * Таблица используется в окнах дампов и отладчике.
    * Символы можно делить на группы переводами строки, которые при обработке игнорируются.
    * Файлы кодировок находятся в каталоге __data__ и имеют расширение __.chr__.
* __files__: Фильтр, который будет использоваться в диалоге выбора файлов для загрузки.
* __debug__ (0/1): Используется для отладочных конфигураций, которые по умолчанию не показываются в общем списке. Включить вывод таких конфигураций можно параметром __show_debug_versions__ в ini-файле. В веб-сборку такие конфигурации не попадают вовсе: скрипт упаковки пропускает их вместе с их образами ПЗУ.
* __radix__ (2/8/10/16): Система счисления, в которой записаны числа этого файла без префикса. По умолчанию 10, то есть всё как обычно; параметр нужен машинам, документация которых написана в другой системе. У всех конфигураций БК стоит 8, и адреса в них выглядят так же, как в описании машины: `@memory[177660-177661]`, `start_address = 140000`.

#### Правило одно

Если объявлен __radix__, в этой системе счисления читается **любое** число файла без префикса. Величины, которые к машине отношения не имеют &ndash; частоты, размеры, геометрия, задержки, счётчики, &ndash; пишутся с префиксом __\___:

~~~
system {
	radix = 8
}

cpu : 1801vm1 {
	clock = _4000000              // 4 МГц, десятичное
	start_address = 140000        // 0140000, адрес машины
}

port-kbd-state : port {
	size = _16                    // 16 разрядов
	mask = 100                    // 0100, маска разряда 6
}
~~~

Исключение одно: номера разрядов в квадратных скобках соединения (`~page = port-sys.alt[12-14]`) всегда десятичные. Это часть синтаксиса соединения, а не число машины.

Явный префикс сильнее радикса, поэтому в файле с __radix = 8__ можно писать `$A5`, и это по-прежнему шестнадцатеричное. Значит, данные, которые удобнее читать в другой системе (образец в памяти, коды символов), можно оставить как есть.

Радикс относится к загруженной машине целиком: его выставляет загрузка конфигурации, а сценарий может переопределить командой [RADIX](SCRIPTING.md#radix). Числа, которые эмулятор читает не из конфигурации машины &ndash; настройки в ini-файле, описание формата ленты, &ndash; остаются десятичными всегда.

### Машины с несколькими процессорами

Процессоров в конфигурации может быть сколько угодно. Один из них обязан называться __cpu__: он ведущий, и его частота &ndash; временная база всей машины. В его тактах считаются `clock_counter`, задержки сценариев и команда [WAIT](SCRIPTING.md#wait), сколько бы остальные ни успели за то же время.

У каждого процессора своё адресное пространство (параметр __mapper__) и свой тактовый домен. Устройство попадает в домен процессора, указанного в __clock_source__, и тактуется его тактами; по умолчанию это __cpu__, поэтому однопроцессорные конфигурации писать как раньше.

~~~
// Центральный процессор: ведущий, задаёт время машины
cpu : 1801vm2 {
	clock = _8000000
}

// Периферийный: своя частота, своя память
ppu : 1801vm2 {
	clock = _6250000
	mapper = ppu-mapper
}

// Экран тактуется от периферийного процессора, а не от ведущего
display : uknc-display {
	clock_source = ppu
}

mapper     : memory-mapper { ... }
ppu-mapper : memory-mapper { ... }
~~~

Общей памяти между процессорами нет: у каждого свой диспетчер. Но одно и то же устройство памяти можно указать в обоих &ndash; диспетчеры хранят на устройства невладеющие ссылки, и ничто не мешает включить один блок ОЗУ в две карты, с разными базовыми адресами. Так же в оба диспетчера включается устройство, регистры которого видны обоим процессорам.

Процессоры чередуются по командам, в точном соотношении частот: эмулятор приводит их к общему времени через НОК частот, поэтому 8 и 6,25 МГц дают ровно 32 такта одного на 25 тактов другого. Прогон при этом остаётся воспроизводимым побайтно, и снимок экрана годится в эталоны так же, как у однопроцессорной машины.

Отладчик открывается на любой из процессоров: если их больше одного, пункт меню предлагает выбор. Сценарии и MCP обращаются к ним по именам &ndash; `LOG ppu.registers`, `COMMAND ppu.stop()`.

Проверочная конфигурация &ndash; `deploy/computers/bk/2cpu-test.cfg`, сценарий `tests/scripts/boot-2cpu.ecat`.

### memory-mapper

Главный диспетчер адресного пространства процессора.

~~~
mapper : memory-mapper {
	portstomemory = 0
	cancelinit = $8000
	config = port1

	@memory[*][$0000-$07FF] = bios {mode = r}
	@memory[value:mask][addr1-addr2] = device
	@memory[addr1-addr2] = device[start_addr]

	@port[number] = device
}
~~~

В конфигурации Memory Mapper три основных раздела:

* Основные параметры:
    * __portstomemory__ (0/1): Отображение портов на память. По умолчанию &ndash; 0;
    * __wideports__ (0/1): Разрядность номеров портов (8/16). По умолчанию &ndash; 8;
    * __cancelinit__: При получении какого адреса отменится запись ___@memory[*]___. Обычно используется для отображения системного ПЗУ на начальные адреса памяти после сброса.
    * __config__: Устройство (порт или регистр), содержащее регистр конфигурации диспетчера. Значения этого регистра используются в записях ___@memory___. Устройство должно иметь один из интерфейсов __~value__ или __~out__.
* Отображение адресов памяти. Поиск подходящего условия происходи сверху вниз, поэтому первые строки имеют приоритет. Примеры записей:
    * __@memory[$0000-$7FFF] = ram__
        * Диапазон памяти $0000-$7FFF безусловно отображается на устройство __ram__;
    * __@memory[*][$0000-$07FF] =  bios {mode = r}__
        * Диапазон памяти $0000-$07FF после сброса отображается на устройство __bios__ при операциях чтения;
        * После получения адреса с маской __cancelinit__ эта запись блокируется;
        * Данная запись должна быть первой в списке, чтобы иметь приоритет над остальными.
    * __@memory[$E000-$FFFF] = dma {mode = w}__
        * Диапазон памяти $E000-$FFFF отображается на устройство __dma__ при операциях записи;
    * __@memory[$F700-$F72F] = fdc {mode = w, addr_mask=$24, addr_value=0}__
        * Диапазон $F700-$F72F отображается на устройство __fdc__ при операциях записи, дополнительно адрес при наложении AND-маски $24 должен давать 0.
    * __@memory[$FFB2-$FFB3] = port-kbd-code {mode = r, strict = 1}__
        * Признак __strict__ означает, что диапазон отвечает только на обращения своего режима: запись в такой регистр остается без ответа, как будто устройства нет. Без признака диапазон только для чтения на запись отвечает, но игнорирует ее. Имеет смысл для процессоров с таймаутом магистрали ([1801vm1](#1801vm1--1801vm2)).
    * __@memory[&177714-&177715] = ay {mode = w, through = 1}__
    * __@memory[&177714-&177715] = port-ppi-out {mode = w}__
        * Признак __through__ означает, что запись, принятая этим диапазоном, идет дальше, к следующим подходящим записям списка: один адрес слушают несколько устройств. На БК запись в порт 0177714 попадает и в AY-3-8910, и в выходной регистр порта, от которого сбрасывается мышь. На чтение признак не влияет, в карте памяти (__LOG mapper.map__) диапазон помечается словом __through__.
    * __@memory[1:1][160000-176777] = win3 {or_read = 1}__
    * __@memory[160000-176777] = rom {mode = r}__
        * Признак __or_read__ &ndash; то же самое для чтения: диапазон отдаёт свои данные и передаёт чтение дальше, а шина видит их объединение по ИЛИ. Так устроены окна УК-НЦ (регистр 177054), где ПЗУ и ОЗУ отвечают одновременно; окно из-за этого оказывается для ОЗУ фактически только на запись. В карте памяти помечается словом __or_read__. Признак стоит ставить на тот диапазон, что включается реже: чтение, попавшее в диапазон с __or_read__, ищет по всему остатку списка, и ПЗУ, из которого процессор выполняет код, с этим признаком платило бы поиском за каждую команду.
    * __@memory[0][$0000-$EFFF] = ram0__
	* __@memory[1][$0000-$EFFF] = ram1__
        * В зависимости от значения порта __config__ выбирается одна из страниц памяти.
    * __@memory[$00:$20][$F000-$F3FF] = ram0[$F000]__
	* __@memory[$20:$20][$F000-$F3FF] = mm3[$F000]__
        * В зависимости от значения отдельного бита config [value:mask] диапазон отображается либо на страницу памяти, либо на страничный менеджер. Начальный адрес на устройствах &ndash; $F000;
* Распределение портов (при отключенном отображении на память).
    * __@port[$F4] = port-keyboard__
        * Порт $F4 отображается на устройство __port-keyboard__.

* Интерфейсы
    * __~config__{?, in}: Может использоваться вместо параметра __config__ для более гибкого подключения управляющих устройств.

## CPU
### Общие параметры
~~~
cpu : z80 {
	clock = 5000000
	debug = 0
	stopped = 0
	breakpoints = $36B, $1800
}
~~~
* __clock*__: Частота процессора, Гц. Частота процессора с именем __cpu__ становится первичной частотой всей системы.
* __mapper__: Имя диспетчера адресного пространства этого процессора. По умолчанию &ndash; __mapper__. Нужен только там, где процессоров несколько и у каждого своя память.
* __debug__ {0/1}: Запуск процессора в режиме отладки. Имеет смысл использовать с предустановленными точками останова.
* __stopped__ {0/1}: Останов процессора при запуске машины. Данный параметр удобно использовать при отладке, чтобы ещё до запуска машины открыть отладчик или другие окна, поставить точки останова и т.&nbsp;д. После настройки, машина запускается кнопкой в отладчике. При использовании совместно с предыдущим параметром, имеет над ним приоритет.
* __breakpoints__: Список точек останова, задаваемых при старте машины. Адреса разделяются запятыми и/или пробелами, каждый адрес записывается в обычном числовом формате ($ &mdash; шестнадцатеричный, &amp; &mdash; восьмеричный, # &mdash; двоичный).

### 1801vm1 / 1801vm2

Процессоры серии К1801 с системой команд PDP-11. Тип __1801vm1__ соответствует
К1801ВМ1 (без команд расширенной арифметики MUL/DIV/ASH/ASHC, при их выполнении
происходит прерывание по вектору 010), тип __1801vm2__ &ndash; К1801ВМ2, где эти
команды реализованы.

~~~
cpu : 1801vm1 {
	clock = 3000000
	start_address = $8000
	~irq2 = !timer.out
	~virq = !keyboard-int.out
	~vector = kbd-vector.value
}
~~~

* Параметры
    * __start_address__: Начальный адрес, задаваемый внешними цепями процессора. После сброса PC берется из ячейки по этому адресу, PSW &ndash; из следующей. Пультовый (HALT) режим использует следующую пару ячеек, со смещениями 4 и 6. По умолчанию &ndash; $8000 (0100000).
    * __reply_delay__: Задержка ответа памяти в периодах тактовой частоты (tn). Задает длительность циклов магистрали, а через них время выполнения всех команд: чтение 7T + tn, запись 10T + tn, чтение-модификация-запись 13T + 2tn. По умолчанию &ndash; 2, как у БК0010 на 3 МГц. У БК0011М на 4 МГц &ndash; 4: ОЗУ там обслуживает контроллер экрана, и процессор ждет его дольше; при этом MOV (R0)+,(R1)+ длится 45 тактов. У УК-НЦ &ndash; 5: динамическое ОЗУ, общее с видеоконтроллером; так тест SPEED показывает те же 280 тысяч сложений регистр-память в секунду, что и настоящая машина.
    * __halt_sel__: База векторов пультового режима &ndash; вывод SEL процессора. По умолчанию 0: вход в режим идёт обычной ловушкой через __halt_vector__, как на БК. Ненулевое значение (у УК-НЦ 160000) включает настоящий пультовый режим ВМ2. Команда HALT и внешний запрос __~halt__ входят в него вектором `halt_sel | 0170`: вектор `halt_sel | 004` у ВМ2 означает зависание магистрали, и монитор УК-НЦ по нему регистров прерванной программы не сохраняет.

Команды плавающей арифметики FIS (FADD, FSUB, FMUL, FDIV, коды 075000-075037) у ВМ2 **не аппаратные**: при ненулевом __halt_sel__ команда уводит процессор в пультовый режим по вектору `halt_sel | 010`, и арифметику выполняет пультовая программа &ndash; у УК-НЦ её кладёт в ОЗУ центрального процессора периферийный. Взведённый разряд 7 у __halt_sel__ означает, что такой программы нет, и тогда это резервная команда (вектор 010). Без этого дисковый Бейсик УК-НЦ отвечал «Ошибка» на любое арифметическое действие.

#### Пультовый режим

У К1801ВМ2 есть пультовый (консольный) режим со своим набором команд и **теневой парой регистров** &ndash; КРСК (копия счётчика команд) и КРСП (копия слова состояния). При входе в режим состояние прерванной программы уходит не на стек, а в эту пару, а вектор берётся как `halt_sel | смещение`.

Команды, доступные только в этом режиме:

| Код | Мнемоника | Действие |
| --- | --- | --- |
| 012 | RUN | КРСК &rarr; PC, КРСП &rarr; PS, снятие режима и пуск |
| 016 | STEP | то же, но после одной команды процессор возвращается в режим; прерывания на этот шаг замаскированы |
| 021 | MFPM | (R5)+ &rarr; R0, чтение памяти прерванной программы |
| 022 | MFPC | КРСК &rarr; R0 |
| 024 | MFPS | КРСП &rarr; R0 |
| 031 | MTPM | R0 &rarr; -(R5) |
| 032 | MTPC | R0 &rarr; КРСК |
| 034 | MTPS | R0 &rarr; КРСП |

Есть только у __1801vm2__: у ВМ1 эти коды остаются резервными командами, и поведение БК не меняется. Пуск по вектору (__start_vector__) сам по себе является входом в пультовый режим &ndash; подача питания приводит процессор туда же, куда команда HALT.

Мнемоники и коды взяты из ПЗУ УК-НЦ, где пультовый монитор объявляет их в начале своего раздела.

* Интерфейсы
    * __~virq{1, in}__: Запрос векторного прерывания по магистрали.
    * __~vector{16, in}__: Адрес вектора, выставляемый запрашивающим устройством. Считывается в момент активации __~virq__.
    * __~irq2{1, in}__: Запрос прерывания с фиксированным вектором 0100.
    * __~dclo{1, in}__: Авария питания. Пока линия активна (ноль), процессор не выполняет ни одной команды; отпущенная, она запускает его с начального адреса. На УК-НЦ этой линией периферийный процессор держит и поднимает центральный (разряд 5 его регистра 177716): ПЗУ стоит на стороне ПП, и машину поднимает именно он. Незанятая линия процессору не мешает, поэтому в конфигурациях БК её нет.
    * __~aclo{1, in}__: Авария сети. **Снятие** линии при работающем процессоре &ndash; прерывание по вектору 024, и оно старше пульта и всех устройств; запрещают его только оба разряда приоритета слова состояния сразу. Пока процессор держат линией __~dclo__, запрос не появляется. На УК-НЦ линией распоряжается периферийный процессор разрядом 15 своего регистра 177716, и резидент винчестера так сообщает центральному об окончании переноса: кладёт свой адрес в вектор 024, дёргает линию и возвращает вектор на место. Не подключённая линия стоит снятой и запросов не даёт.
    * __~iako{16, out}__: Подтверждение векторного прерывания (сигнал IAKO магистрали): в момент, когда процессор берёт прерывание, линия на мгновение показывает взятый вектор и возвращается в ноль. Устройство с однократным запросом снимает по нему свой. Не подключённая линия ничего не стоит.
    * __~init{1, out}__: Сигнал INIT магистрали: импульс 1-0 по команде RESET. Подключённые устройства (например, [dl11](#dl11)) сбрасывают по нему свои регистры; сам процессор не сбрасывается.
    * __~halt_mode{1, out}__: Процессор в пультовом режиме. Заводится на __~config__ диспетчера у машин, где от режима зависит карта памяти.
    * __~irq3{1, in}__: Запрос прерывания с фиксированным вектором 0270.
    * __~halt{1, in}__: Запрос перехода в пультовый (HALT) режим.

__Примечания__:

* Все входы прерываний имеют активный низкий уровень, как сигналы магистрали МПИ. Для источников с положительной полярностью используйте инверсию: ___~irq2 = !gen50hz.out___.
* Запрос защелкивается в момент активации и снимается при его обслуживании. Это позволяет использовать в качестве источника короткие импульсы, например от устройства [generator](#generator), которые при чисто уровневом входе терялись бы между командами.
* Обращение по адресу, на котором не отображено ни одно устройство, заканчивается таймаутом магистрали: текущая команда прерывается и происходит прерывание по вектору 004. ПЗУ БК так определяют, какие блоки памяти действительно установлены, поэтому дырки в карте памяти должны оставаться дырками. Диапазон, отображенный только на чтение, отвечает и на запись &ndash; она просто игнорируется, как в реальном ПЗУ. Если же диапазон помечен признаком __strict__ (см. [memory-mapper](#memory-mapper)), обращение другого режима остается без ответа: так ведет себя регистр кода клавиши 0177662 на БК0010, и по таймауту при записи в него дисковые системы отличают БК0010 от БК0011М.
* Процессор работает со словами, поэтому обращения к 16-разрядным регистрам ввода-вывода выполняются целиком. Устройство [port](#port) с параметром __size__ больше 8 при этом отдает и принимает весь регистр, а при побайтном обращении выбирает половину регистра по младшему биту адреса.
* Значения регистров и адреса в окне отладчика выводятся восьмерично, как принято в документации на PDP-11.

## Базовые устройства

### ram
Блок ОЗУ
~~~
ram0 : ram {
	size = 64k
	fill = 0
}
~~~
* __size*__: Размер в байтах.
* __fill__ {0-255|random}: Байт для заполнения при холодном сбросе. По умолчанию &ndash; 0. При значении _random_ при холодном сбросе память будет заполняться случайными значениями.

### rom
Блок ПЗУ
~~~
bios : rom {
	size = 2k
	image = TestZ80.bin
}

ram-mapper : rom {
	data = {0,0,2,3,1,1,2,3}
}

~~~
* __size*__: Размер в байтах. Обязателен при загрузке файла через параметр __image__.
* __fill__: Байт для заполнения пустой области. По умолчанию &ndash; $FF.
* __files__: Фильтр окна выбора файла, как у [fdd](#fdd). ПЗУ с этим параметром &ndash; сменное (картридж): его __image__ меняется в [редакторе расширений](#редактор-расширений). Системные ПЗУ его не задают, и в редакторе их нет.
* ПЗУ без __image__ и без __data__ &ndash; пустое гнездо картриджа: оно занимает свои __size__ байт и отвечает байтом __fill__.
* __image*__: Имя файла образа:
    * Поддерживаются форматы [Intel Hex](https://ru.wikipedia.org/wiki/Intel_HEX) (*.hex), двоичный (другие расширения).
    * Файл *.hex будет загружен с начального адреса на устройстве, независимо от указанного в самом файле.
    * Размер файла должен быть меньше или равен __size__. Остаток будет заполнен байтом __fill__ либо повторами образа, если задан __repeat__.
    * Файл должен находиться в одном из следующих мест:
        * В том же каталоге, что и __.cfg__;
        * В подкаталоге __files__ рядом с .cfg;
        * В подкаталоге __software__, совпадающем с подкаталогом __.cfg__.
* __repeat__: Если 1, образ размножается по всей области __size__: так ведет себя микросхема, у которой не декодированы старшие адресные линии. По умолчанию &ndash; 0, остаток заполняется байтом __fill__.
* __data*__: Содержимое ПЗУ в виде строки чисел через запятую.

Должен присутствовать хотя бы один из параметров &mdash; __image__ или __data__.

### port
Единичный адресуемый регистр/порт
~~~
port-videomode: port {
    size = 8
    default = $02
}
~~~
* Параметры:
    * __size__: Ширина регистра в битах. По умолчанию &ndash; 8;
    * __flipmask__: Маска для инверсии значения по отрицательному фронту интерфейса __flip__. По умолчанию &ndash; $FFFFFFFF.
    * __default__: Значение после сброса. По умолчанию &ndash; 0.
    * __mask__: AND-маска для записываемых значений. Совместно с __default__ позволяет задать неизменяемые биты. По умолчанию &ndash; $FFFFFFFF.
    * __constant_return__: Возвращаемое значение, если у порта нет функции чтения. По умолчанию не используется, порт при чтении возвращает записанное в него ранее значение.
    * __access_mode__ (r, w, rw): какие виды доступа вызывают срабатывание интерфейса __access__. По умолчанию &ndash; rw; 
    * __alt_bit__: Номер разряда записываемого значения, выбирающего второй банк регистра. По умолчанию не используется.
    * __alt_default__: Значение второго банка после сброса. По умолчанию &ndash; 0.


* Интерфейсы:
    * __~data{=size=, in}__: Входные данные.
    * __~value{=size=, out}__: Выходные данные.
    * __~alt{=size=, out}__: Выходные данные второго банка.
    * __~access{1, out}__: Выдает импульс отрицательной полярности в момент записи или чтения значения.
    * __~flip{1, in}__: При отрицательном фронте по этому интерфейсу происходит инверсия значения порта по маске __flipmask__. 
    * __~reset{1, in}__: При отрицательном фронте по этому интерфейсу происходит запись в порт значения __default__. 

__Примечания__:

* При __size__ больше 8 порт становится двухбайтным. Процессоры со словной шиной ([1801vm1](#1801vm1--1801vm2)) читают и пишут такой регистр целиком, а при побайтном обращении выбирается половина регистра по младшему биту адреса. Для 8-разрядных портов поведение не меняется.
* Биты, подключенные к входу __~data__, замещают соответствующие биты регистра, поэтому чтение порта возвращает текущее состояние этих линий. Остальные биты сохраняют записанное в порт значение. Так, например, в регистр состояния клавиатуры БК заводится триггер готовности:

~~~
port-kbd-state : port {
	size = 16
	~data[7] = kbd-ready.out[0]
}

kbd-ready : register {
	~s = keyboard.ready
	~r = port-kbd-code.access
}
~~~

* Если задан __alt_bit__, за одним адресом стоят два регистра, и указанный разряд записываемого значения выбирает, в какой из них попадет запись. Чтение всегда возвращает основной банк, второй доступен только через интерфейс __~alt__. Так устроен системный регистр 0177716 БК0011М, где запись с установленным разрядом 11 управляет памятью, а без него &ndash; магнитофоном и звуком:

~~~
port-sys : port {
	size = 16
	alt_bit = 11
	alt_default = $0002
}

win0 : page-mapper {
	~page = port-sys.alt[12-14]
}
~~~

### port-address
Единичный адресуемый регистр/порт, запоминающий адрес обращения, а не данные.
~~~
port-video: port-address {
    store_on_read = 1
}
~~~
Основные параметры и интерфейсы аналогично __port__.
* Дополнительные параметры:
    * __store_on_read__ (0, 1): Запоминать ли значение при чтении. По умолчанию &ndash; выключено.

### ram-address
Блок ОЗУ, использующий часть адреса для сохранения значения. Применяется для эмуляции программных переключателей (soft-switches), где адрес обращения кодирует команду.

~~~
port-C1xx : ram-address {
	size = 256
	address_shift = 4
	address_mask = $0F
	value_shift = 0
	value_mask = $0F
	store_on_read = 1
}
~~~
Наследует параметры __ram__.

* Дополнительные параметры:
    * __address_shift__: Сдвиг адреса для извлечения адреса в ОЗУ. По умолчанию &ndash; 4.
    * __address_mask__: Маска для извлечения адреса после сдвига. По умолчанию &ndash; $0F.
    * __value_shift__: Сдвиг адреса для извлечения записываемого значения. По умолчанию &ndash; 0.
    * __value_mask__: Маска для извлечения записываемого значения после сдвига. По умолчанию &ndash; $0F.
    * __store_on_read__ (0/1): Сохранять ли значение при чтении. По умолчанию &ndash; выключено.

* Интерфейсы:
    * __~we{1, in}__: Разрешение записи.
    * __~access{1, out}__: Импульс при обращении.

### register
Регистр-защелка или буфер. Запоминает входное значение по стробу на входе записи или транслирует входы на выходы.
~~~
latch : register {
    type = latch-pos
	~in[0-3] = port-user.B[0-3]
	~c = port-user.CH[3]
}
~~~
* Параметры:
    * __type__: Тип регистра:
        * __buffer__: Входы транслируются на выходы. Интерфейс __~c__ не используется.
        * __flip-flop-pos__: Запись по положительному фронту на входе __c__.
        * __flip-flop-neg__: Запись по отрицательному фронту на входе __c__.
        * __latch-pos__: Передача при __c__=0 и хранение при __c__=1.
        * __latch-neg__: Передача при __c__=1 и хранение при __c__=0.
        * По умолчанию &ndash; __flip-flop-pos__;
    * __default__: Значение после сброса. По умолчанию &ndash; 0.

* Интерфейсы:
* __~in{16, in}__: Входные данные.
* __~c{1, in}__: Строб записи.
* __~out{16, out}__: Выход записанных данных. 

### mux
Мультиплексор. Транслирует на выход один из двух входов в зависимости от состояния управляющей линии.
~~~
port-mux : mux {
	~a[6] = kngmd-res.out[0]
	~a[7] = ikbd.out[0]
	~b    = $FF
	~s    = ppa.CH[3]
}
~~~
* Параметры: специфических параметров нет.

* Интерфейсы:
    * __~a{8, in}__: Первый вход, транслируется на выход при __s__=0.
    * __~b{8, in}__: Второй вход, транслируется на выход при __s__=1.
    * __~s{1, in}__: Линия выбора входа.
    * __~out{8, out}__: Выход.

Выход пересчитывается при любом изменении на входах __a__, __b__ или __s__. Входы можно подключать частично (по отдельным битам или диапазонам) &ndash; неподключенные биты остаются в единичном состоянии, как и у прочих интерфейсов.

В приведенном примере порт B микросхемы i8255 имеет две функции, переключаемые битом PC[7]: при __s__=0 читаются биты состояния (6 и 7), при __s__=1 &ndash; константа $FF.

### generator
Генератор импульсов заданной частоты
~~~
gen50hz: generator {
	frequency = 50
	polarity = positive
	length = 1
}
~~~
* __frequency*__: Частота импульсов, Гц.
* __polarity__: Полярность импульсов. Значения: _positive_, _pos_, _p_, _1_, _negative_, _neg_, _n_, _0_). Значение по умолчанию: _positive_.
* __length__: Длина импульса в отсчетах системного генератора. Значение по умолчанию: 1.
    * В связи с особенностями эмуляции, минимально возможная длина импульса фактически будет равна длине команды CPU, на которую он попадет.

Интерфейсы:
* __~out{1, out}__: Выход генератора.
* __~enable{1, in}__: Разрешение работы генератора. Если не подключен, генератор работает всегда.

### page-mapper
Страничный диспетчер
~~~
mm2 : page-mapper {
	frame = 16k
	@page[0] = ram0
	@page[1] = ram1
	@page[2] = ram2
	@page[3] = ram3
	~page    = portFB.value[2-3]
	~segment = portFB.value[0-1]
}
~~~
Параметры:
* __frame__: Размер сегмента страницы памяти, а также выходного окна. По умолчанию равен размеру страницы.
* __@page[]__: Перечень устройств-страниц.

Интерфейсы:
* __~page{?, in}*__: Номер выбранной страницы.
* __~segment{?, in}__: Номер сегмента в странице.

Если сегментирование страниц не используется, __frame__ и __~segment__ не указываются. Если используется только одна страница, необходимо указать интерфейс __~page=0__.

Количество страниц и сегментов должно соответствовать ширине соответствующих интерфейсов. В данном примере 4 страницы размером по 64кб, в каждой 4 сегмента по 16к, что соответствует двум двухбитным интерфейсам.

### plane-pair
Адресное пространство поверх двух байтовых планов памяти: один хранит младшие байты слов, другой старшие.

~~~
cpu-ram : plane-pair {
	low = plane1
	high = plane2
	size = _64k
}
~~~

Так устроена память центрального процессора УК-НЦ: слово по адресу A &ndash; это байт A/2 плана 1 плюс байт A/2 плана 2, поэтому 64 КБ адресов стоят по 32 КБ каждого плана. Видеоконтроллер читает те же планы побайтно, ради чего память так и разложена. Байтовое обращение выбирает план по разряду 0 адреса, словное берёт по байту из каждого.

* Параметры
    * __low*__: Устройство памяти с младшими байтами (чётные адреса).
    * __high*__: Устройство памяти со старшими байтами (нечётные адреса).
    * __base__: Смещение в планах, которому соответствует нулевой адрес устройства. По умолчанию 0. Верхняя часть планов УК-НЦ занята экраном и процессору недоступна.
    * __size__: Размер адресного пространства. По умолчанию &ndash; вдвое больше глубины планов; 16-разрядному процессору столько не адресовать, поэтому обычно указывается явно.

* Поля для сценариев
    * __planes__: Имена планов.
    * __base__: Смещение в планах.

### indirect-memory
Косвенный доступ к памяти через регистр адреса и регистры данных.

~~~
planes12 : plane-pair {
	low = plane1
	high = plane2
}

pp-indirect : indirect-memory {
	@data[0] = plane0 {width = 8}
	@data[1] = planes12 {scale = 2}
}
~~~

Регистр адреса лежит по нулевому смещению, регистр данных n &ndash; по смещению (n+1)*2. Запись в регистр адреса защёлкивает слово из каждого устройства-приёмника; чтение регистра данных отдаёт защёлку, запись кладёт слово в его устройство.

У приёмника в `{...}` могут стоять два признака:

* __scale__ &ndash; регистр адреса умножается на это число, прежде чем дойти до приёмника. Регистр УК-НЦ хранит индекс байта в планах, а у __plane-pair__ по слову на два адреса, отсюда `scale = 2`. Без него индекс делился бы на 2: запись по «адресу» 070075 портила слово 070074 &ndash; так ломался загруженный с дискеты Бейсик, и SIN с COS уводили машину на HALT.
* __width__ = 8 &ndash; приёмник байтовый (план 0): защёлка держит один байт.

Байтовая запись в регистр ведёт себя как на машине (и как в UKNCBTL): в регистр адреса и в регистр байтового приёмника это слово с байтом на своей половине и нулём на другой, в регистр словного приёмника &ndash; только в свою половину, то есть в один план из двух.

**Защёлка существенна**: повторное чтение регистра данных память не перечитывает. Программа, которой нужно свежее слово, пишет адрес заново &ndash; хотя бы тот же самый.

Этим на УК-НЦ процессоры достают память, которую не адресуют: у центрального 176640/176642 (планы 1 и 2), у периферийного 177010/177012/177014, и через последний он видит все 192 КБ, включая память центрального. Обратное неверно: план 0 центральному процессору недоступен вовсе.

* Параметры
    * __@data[]*__: Перечень устройств, к которым обращаются регистры данных.
    * __address_mask__: Маска регистра адреса. По умолчанию $FFFF.
    * __auto_increment__ (0/1): Наращивать адрес после записи в регистр данных. По умолчанию выключено.

* Интерфейсы
    * __~address{16, out}__: Содержимое регистра адреса. От него рисует [uknc-graphics](#uknc-graphics).

* Поля для сценариев
    * __address__: Содержимое регистра адреса.
    * __targets__: Регистры данных и устройства, к которым они обращаются.

## Периферия

### speaker
Однобитный спикер
~~~
sound : speaker {
    mode = level
    lpf = 5000
	~input = cpu.inte
	~mixer[0-2] = timer.output[0-2]
}
~~~

Параметры:
* __mode__ (level/flip): Режим работы входа __input__:
    * __level__: Используется текущий уровень сигнала.
    * __flip__: Значение бита инвертируется по отрицательному фронту входного сигнала.
* __lpf__: Частота среза для фильтра нижних частот (используется фильтр Баттерворта второго порядка, -12 дБ/октаву). По умолчанию отключен (0).
* __mix__: Список других звуковых устройств (через `|`), чей сигнал подмешивается к выходу динамика, например `mix = ay`. Такие устройства (сейчас это [ay8910](#ay8910) и [covox](#covox)) сами звук не выводят: в машине один аудиовыход, и это динамик.

Интерфейсы:
* __~input{1, in}__: Вход однобитного спикера.
* __~mixer{8, in}__: Вход для нескольких однобитных каналов.
* __~enable{8, in}__: Разрешение входа __input__: сигнал доходит до динамика, только пока на всех подключенных битах 1, иначе вход считается нулем. Это элемент И перед динамиком; неподключенный интерфейс ничего не запрещает. У Микроши динамик стоит за И-НЕ из выхода канала 2 таймера и PC1 (гейт канала 2 &ndash; PC2):

~~~
sound : speaker {
	~input     = timer.output[2]
	~enable[0] = port-keyboard.CL[1]
}
~~~

Пока гейт закрыт, выход таймера держится в 1, и PC1 сам дергает динамик, как у программ, выводящих звук без таймера. Бит надо указывать явно (`~enable[0]`): без диапазона однобитный источник занимает весь интерфейс и обнуляет остальные его биты, и разрешения не будет никогда.

__Примечания__:
* Должно быть создано как минимум одно соединение интерфейса __input__ либо __mixer__. Все использованные входы микшируются пропорционально.
* Сигналы динамика и устройств из __mix__ усредняются, поэтому с подключенным генератором сам динамик звучит вдвое тише. Устройство, вынутое из разъема [connector](#connector), в усреднении не участвует.
* __idle_share__ (1/0) у звукового устройства с __mix__: занимает ли источник долю, пока молчит. По умолчанию 1. При 0 источник входит в смесь, только когда его сигнал впервые после сброса отличается от того, что он давал сразу после сброса (проверка раз в миллисекунду): плата, в которую программа не пишет, не приглушает остальной звук. Поле __mixed__ перечисляет источники, занимающие долю сейчас (`-`, если ни одного); оно считается и без звуковой карты.
* Уровень за время одного отсчета звуковой карты усредняется с весом по тактам процессора: команда, державшая уровень вдвое дольше, дает вдвое больший вклад. При счете по командам искажались уровни ЦАП и ширина импульсов однобитного вывода.
* Чтобы работал регулятор громкости, устройство должно называться __sound__.

### ay8910

Программируемый звуковой генератор AY-3-8910 (AY-3-8912, КР580ВИ8910): три
тональных канала, генератор шума, генератор огибающей и два 8-разрядных
порта. Устройство не имеет собственного аудиовыхода, его надо перечислить в
параметре __mix__ у [speaker](#speaker). Регистры доступны через карту памяти
или портов; как обращения шины превращаются в выбор регистра и запись данных,
задает параметр __bus__.

~~~
ay : ay8910 {
	bus = bk
	frequency = 1714275
}

sound : speaker {
	~input = port-sys.value[6]
	mix = ay
}

mapper : memory-mapper {
	@memory[$FFCC-$FFCD] = ay {mode = w}
	@memory[$FFCC-$FFCD] = port-ppi {mode = r}
}
~~~

Параметры:
* __bus__ (direct/bk/word): Протокол подключения к шине.
    * __direct__ (по умолчанию): два адреса, четный &ndash; номер регистра, нечетный &ndash; данные; чтение по нечетному адресу отдает выбранный регистр.
    * __bk__: приставка к БК на выходных линиях порта 0177714. Запись слова в порт выбирает регистр, запись байта по четному адресу записывает данные; и номер, и данные проходят через инвертирующие линии порта, поэтому программа пишет их дополнение до 0377. Запись байта по нечетному адресу до микросхемы не доходит. Чтение микросхемой не обслуживается, поэтому в карте памяти устройство ставится с `mode = w`, а порт, отдающий состояние джойстика, &ndash; с `mode = r`.
    * __word__: звуковой модуль УК-НЦ (Aberrant Sound Module). Запись слова выбирает регистр, запись байта по любому из двух адресов записывает данные; инверсию магистрали снимают буферы модуля, поэтому значения прямые. Чтение отдает 0, как в UKNCBTL.
* __frequency__: Тактовая частота микросхемы, Гц. По умолчанию 1714275 (12 МГц / 7, как у плат для БК).

Интерфейсы:
* __~porta{8, out}__, __~portb{8, out}__: Выходы портов ввода-вывода (регистры 14 и 15).

__Примечания__:
* Период тона в регистрах задается в единицах 16 тактов, шума и огибающей &ndash; в единицах 16 тактов на шаг; нулевой период считается единицей, как у настоящей микросхемы. Уровни громкости логарифмические, 16 ступеней; таблица взята из MAME.
* Микросхему можно включить в [connector](#connector): вынутая из разъема, она не принимает записи, не тактируется и молчит, а подключенная снова начинает с состояния после сброса. Поле __plugged__ показывает, подключена ли она.
* До первой записи после сброса все регистры нулевые и выход молчит при любой фазе генераторов, поэтому генераторы до неё стоят, а не считают такты впустую. Долю в миксе молчащей микросхемы решает __idle_share__ у [speaker](#speaker).
* Поля для сценариев: __regs__ (все 16 регистров, `regs(от,до)` &ndash; диапазон), __register__ (выбранный регистр), __level__ (сумма уровней каналов, 0-3000), __envelope__ (текущее значение огибающей, 0-15).

### covox

Covox &ndash; восьмиразрядный ЦАП на выходных линиях параллельного порта: уровень
на выходе равен байту, оставленному программой в порту, 0 &ndash; минимум, 0377
&ndash; максимум. Своего регистра и тактирования у него нет, частоту выборки
задает программа тем, как часто пишет в порт. Как и [ay8910](#ay8910),
собственного аудиовыхода не имеет и перечисляется в параметре __mix__ у
[speaker](#speaker).

~~~
covox : covox {
	~input = port-ppi-out.value[0-7]
}

sound-card : connector {
	devices = ay|covox
	default = ay
	kind = sound
}

sound : speaker {
	~input = port-sys.value[6]
	mix = ay|covox
}
~~~

Интерфейсы:
* __~input{8, in}__: Входы ЦАП. На БК это младший байт выходного регистра порта 0177714, без инверсии (как в BKBTL).

__Свойства для сценариев__: __value__ &ndash; байт на входе ЦАП, __plugged__
&ndash; подключен ли он.

__Примечания__:
* На БК AY-3-8910 и Covox принимают запись в один и тот же порт, поэтому в конфигурациях описаны оба, а подключенную приставку выбирает [connector](#connector). Программа для Covox (демо TDR) выводит выборки байтами в порт, и включенный AY принял бы их за данные выбранного регистра.

### scan-keyboard
Клавиатура с матрицей сканирования
~~~
keyboard : scan-keyboard {
	~scan = port-keyboard.A
	~output = port-keyboard.B
	~shift = port-keyboard.CH[5]
	~ctrl = port-keyboard.CH[6]
	~ruslat = port-keyboard.CH[7]
	~ruslat_led = !port-keyboard.CL[3]
	map = rk.kbd
	ctrl = ctrl
	shift = shift
	ruslat = caps
}
~~~
Параметры:
* __map__: Файл с раскладкой клавиатуры (см. ниже).
* __ctrl__: Назначение кнопки Control.
* __shift__: Назначение кнопки Shift.
* __ruslat__: Назначение кнопки переключения Рус-Лат.
* __keys__, __picture__: Нативная таблица клавиш и рисунок клавиатуры, см. [Экранная клавиатура](#экранная-клавиатура).

Интерфейсы:
* __~scan{?, in}__: Линии сканирования. Ширина устанавливается автоматически по количеству колонок в @layout.
* __~output{?, out}__: Выходные линии. Ширина устанавливается автоматически по количеству строк в @layout.
* __~shift{1, out}__: Линия Shift;
* __~ctrl{1, out}__: Линия Control;
* __~ruslat{1, out}__: Линия Рус-Лат;
* __~ruslat_led{1, in}__: Индикатор Рус-Лат;

Раскладка задается с помощью файла, который представляет собой таблицу соответствия клавиш хоста и позиций матрицы сканирования. Строки соответствует линиям сканирования, столбцы &ndash; выходным линиям.

Несколько клавиш можно указывать через знак "|". Позиции матрицы разделяются пробелом или табуляцией.

После символа клавиши может быть один из двух модификаторов:
* &laquo;_&raquo; &ndash; Shift принудительно отключается;
* &laquo;^&raquo; &ndash; Shift принудительно включается;

Модификаторы используются, когда состояние Shift на эмулируемом компьютере не совпадает с нужным для ввода символа на хосте. Например, при вводе &laquo;:&raquo; Shift нажимается, но на эмулируемой машине этот символ вводится без Shift &ndash; тогда в раскладке на нужной позиции будет &laquo;:_&raquo;, т.е. эта позиция в матрице соответствует двоеточию, но Shift нужно отпустить.

Режим РУС определяется по состоянию входного интерфейса __ruslat_led__. В этом режиме происходит переназначение некоторых клавиш для конвертации раскладки QWERTY в JCUKEN.

Доступные клавиши:
* 0..9, A..Z, f1..f12
* pgup, pgdown, end, home, left, right, up, down
* ret, ret2, caps, esc, space, back, ins, del, del2
* mult, plus, minus, div, num, scroll
* ~ - = \ [ ] : ; " / , .
* _ (подчеркивание, синоним &ndash; under)
* ^ (синоним &ndash; circum)
* __ (двойное подчеркивание) &ndash; клавиша в этой позиции отсутствует.

Синонимы under и circum желательно использовать вместо основных символов, чтобы не путать их с модификаторами Shift.

Файл может находиться вместе с другими файлами компьютера, либо в директории __data__.

Пример файла:
~~~
home    tab     0       8|(     @_  H   P   X
del     ret2    1|!     9|)     A   I   Q   Y
esc 	ret     2|"     :_|*    B   J   R   Z
F1  	back    3|#     ;|+     C   K   S   [
F2      left    4|$     ,|<     D   L   T   \
F3      up      5|%     -|=^    E   M   U   ]
F4      right   6|&     .|>     F   N   V   ^_
__      down    7|'^    /|?     G   O   W   space
~~~

### map-keyboard
Клавиатура, записывающая код клавиши в регистр. Соответствие клавиш и полученного кода задается во внешнем файле.
~~~
keyboard : map-keyboard {
	map = agat.map
	port-value = port-kbd
	ruslat = caps
	port-ruslat = port-kbd-ruslat
	rus-on = 0
	rus-bit = 7
}
~~~

Параметры:
* __map*__: Файл мэппинга клавиш. Должен находиться в каталоге с cfg.
* __port-value*__: Устройство-порт, в которое записывается значение.
* __ruslat__: Кнопка, переключающая раскладку.
* __port-ruslat__: Устройство-порт, в который записывается статус раскладки.
* __rus-on__ (0/1): Значение бита, соответствующее русской раскладке.
* __rus-bit__: Номер используемого бита порта ruslat.
* __rusmode__: Режим индикации Рус/Лат:
    * pin: используется выходной контакт, коды символов от раскладки не зависят.
    * code: коды зависят от раскладки и заданы в файле мэпппинга (модификатор __R__).
    * both: используются оба метода.
* __rus_switches__: Два кода через ___/___, которые клавиатура посылает машине при нажатии кнопки __ruslat__: первый при включении русской раскладки, второй при выключении (у Ириши и БК &ndash; `$0E/$0F`). Работает в режимах __code__ и __both__.
* __case-latch__ (0/1): Буквы с клавиатуры компьютера подчиняются защелке регистра букв и регистру РУС так же, как клавиши экранной клавиатуры: без Shift клавиша машины посылает форму __/L__ нативной таблицы, когда этого требует защелка. По умолчанию 0. Включено у БК.
* __keys__, __picture__: Нативная таблица клавиш и рисунок клавиатуры. См. [Экранная клавиатура](#экранная-клавиатура).
* __vector__, __alt-vector__, __alt-codes__: Вектор прерывания, который клавиатура отдает процессору вместе с кодом, на линию __~vector__. Контроллер БК (К1801ВП1-014) знает два вектора: код, набранный со вторым управляющим модификатором (АР2), и коды из списка __alt-codes__ при любых модификаторах идут через __alt-vector__, остальные &ndash; через __vector__. Восьмибитный код из пары «семибитный код, вектор» делает уже ПЗУ машины. Значение нативной таблицы выше $7F тоже означает __alt-vector__: так записываются клавиши, которые контроллер видит как сочетание с АР2 (ГРАФ у БК0010 &ndash; это СУ+АР2+U), а в порт уходят младшие семь бит. Без __vector__ линия не работает, и значения таблицы уходят в порт как есть. Пример для БК:

~~~
	vector = 60
	alt-vector = 274
	alt-codes = "0,1,2,4,5,6,7,11,13,21"
~~~

Интерфейсы:
* __~vector{16, out}__: Вектор прерывания последнего кода, см. __vector__; у БК к нему подключен `~vector` процессора.
* __~ruslat{1, out}__: Линия Рус-Лат;
* __~ready{1, out}__: Сигнал готовности клавиатуры.
* __~pressed{1, out}__: Признак того, что хотя бы одна клавиша сейчас удерживается. В отличие от __~ready__, снимается при отпускании клавиши. Используется машинами, где ПЗУ отслеживает удержание клавиши, например для автоповтора.
* __~stop{1, out}__: Клавиша, подключенная к линии, а не к матрице кодов: поднимается, пока она нажата. Какая именно &ndash; задает строка __stop__ нативной таблицы клавиш. Есть у обоих типов клавиатур.

Пример файла мэппинга:
~~~
f1:         $84
f2:         $85
f3:         $86

J:          $4A     // J
J/S:        $6A     // j (Shift-J)
J/C:        $0A     // Ctlr-J
J/R:        $EA     // Й 
J/RS:       $CA     // й 
J/RC:       $0A     // Ctlr-J (в русской раскладке) 
~~~

Формат строки:
~~~
клавиша: код
клавиша/модификаторы: код
~~~

* Модификаторы: C &ndash; Control, S &ndash; Shift, R &ndash; русская раскладка. Модификаторы могут комбинироваться, регистр букв в них не важен (`up/r` и `up/R` &ndash; одно и то же).
* Доступные коды клавиш приведены в предыдущем разделе.
* Комментарием считается всё от `//` до конца строки, пустые строки пропускаются &ndash; так же, как в нативной таблице клавиш. Клавишу «/» записывают именем `slash`: слева от `/` стоит имя клавиши, поэтому `/S` &ndash; это запись с пустым именем, а `//S` &ndash; комментарий.
* Разбор строгий, и любая из этих ошибок отменяет загрузку машины с указанием строки: неизвестное имя клавиши, неизвестный или повторенный модификатор, пустое имя или значение, значение, которое не читается как число, и повторная запись для той же клавиши с теми же модификаторами. Раньше такая строка молча попадала в таблицу и не работала, а опечатка в числе и вовсе снимала эмулятор без объяснений.

### Экранная клавиатура

Файл мэппинга отвечает на вопрос «какая клавиша хоста дотягивается до этой
клавиши машины». Экранной клавиатуре нужен ответ на другой вопрос &ndash; «что
шлет вот эта клавиша самой машины», &ndash; и для него заводится вторая,
нативная таблица. Оба параметра общие для __scan-keyboard__, __map-keyboard__
и __uknc-keyboard__:

* __keys__: Файл нативной таблицы клавиш машины.
* __picture__: Рисунок клавиатуры в формате SVG.

Клавиши здесь названы по их роли на целевой машине, а не по клавише хоста:
эти же имена служат идентификаторами элементов в рисунке. Заголовок таблицы
объявляет клавиши-модификаторы, они же считаются залипающими &ndash; машина
хранит их состояние сама, поэтому на рисунке они гаснут не по отпусканию, а по
повторному нажатию:

~~~
shift:      key_shift   // моментальный второй регистр (БК: клавиша со стрелкой вниз)
ctrl:       key_su      // моментальный Control
alt:        key_ar2 once // второй управляющий, переводит код на alt-vector (БК: АР2)
case-upper: key_zagl    // защелка заглавных букв
case-lower: key_str     // защелка строчных букв
rus-on:     key_rus     // отдельная РУС
rus-off:    key_lat     // отдельная ЛАТ
// либо одна клавиша-переключатель вместо пары:
// rus:     key_caps
// либо РУС/ЛАТ сканирующей клавиатуры, регистр которой хранит ПЗУ:
// rus-line: key_ruslat
hold:       key_nr      // модификатор, который машина держит сама (УК-НЦ: НР, УПР, ГРАФ, АЛФ, ФИКС)
stop:       key_stop    // дергает линию ~stop вместо кода (БК: СТОП)
repeat:     key_povt    // повторяет последний посланный код (БК: ПОВТ)
reset:      key_sbr     // перезапускает машину вместе с ctrl (Агат: УПР+СБР)
~~~

Одну и ту же роль можно объявить несколько раз: у Агата две клавиши РЕГ, и обе
описаны строкой __shift__.

__hold__ &ndash; роль для машины, которая держит модификатор сама, по коду
нажатия и коду отпускания: эмулятор при этом не хранит ничего, и клавиша шлет
свой код на обоих фронтах, как любая другая. Роль нужна только рисунку: у
указателя одна точка касания, поэтому такая клавиша прижимается щелчком и
отпускается вторым, а не следует за кнопкой мыши. Так описаны НР, УПР, ГРАФ,
АЛФ и ФИКС у УК-НЦ, где регистровые клавиши имеют собственные номера, а
раскладку выбирает ПЗУ машины.

За именем клавиши __shift__, __ctrl__, __alt__ или __hold__ можно поставить признак
__once__. Щелчком на рисунке такая клавиша по-прежнему включается и выключается,
но еще и отпускается сама после первой обычной клавиши &ndash; с рисунка, с
клавиатуры компьютера или из сценария (__KEYDOWN__/__KEYUP__). Отпускание идет
после отпускания той клавиши, так что сама она уходит в машину с модификатором.
Другие модификаторы и защелки РУС/ЛАТ, ЗАГЛ/СТР признак не трогают, поэтому
сочетания вроде СУ+АР2+U набираются как раньше. У БК так устроена АР2:
`alt: key_ar2 once`. Признак у клавиши другой роли, как и неизвестный признак,
отменяет загрузку машины.

Не всякая клавиша шлет код. __stop__ описывает клавишу, подключенную к линии, а
не к матрице: у БК это СТОП, заведенная на вход HALT процессора, и в конфиге
машины стоит `~halt = !keyboard.stop`. __repeat__ &ndash; клавиша, которая
повторяет последний посланный код и держит линию __~pressed__ поднятой, чего
достаточно, чтобы автоповтор ПЗУ подхватил ее сам. __reset__ перезапускает
машину &ndash; ровно то же, что делает Break в окне эмулятора, &ndash; но только
при нажатом модификаторе __ctrl__ (с клавиатуры хоста или с рисунка), как УПР+СБР
у Агата.

Тело таблицы для __map-keyboard__ имеет тот же формат, что и файл мэппинга,
только слева стоит имя клавиши машины. Модификаторы те же (__S__, __C__, __R__)
плюс __L__ &ndash; форма, которую выбирает защелка регистра букв:

~~~
key_1:      $31
key_1/S:    $21
key_a:      $41
key_a/S:    $61
key_a/L:    $61
~~~

Разбор тела такой же строгий, как у файла мэппинга: неизвестный или повторенный
модификатор, пустое имя, нечитаемое значение и вторая запись для той же клавиши
с теми же модификаторами отменяют загрузку машины. Сюда же попадает опечатка в
строке заголовка &ndash; она разбирается как запись тела, и вместо кода в ней
оказывается имя клавиши.

Именно это хостовой таблицей и не выражается: в _bk.map_ есть запись `!/S`, но
записи `1/S` нет вовсе, потому что на хосте `!` &ndash; отдельная клавиша, а на
БК это верхний и нижний регистр одной.

Записи __/L__ есть только у буквенных клавиш, и в этом весь смысл отдельного
модификатора: защелка регистра не должна трогать цифровой ряд. Кроме того,
защелку переворачивает русский регистр &ndash; в КОИ-7 русские заглавные стоят
там же, где латинские строчные, поэтому в ЛАТ заглавную дает код `$41`, а в
РУС `$61`. Без этой инверсии ЗАГЛ и СТР менялись бы местами при нажатии РУС.

Тело таблицы для __scan-keyboard__ &ndash; та же матрица, что и в файле
раскладки __map__: строка &ndash; выходная линия, столбец &ndash; линия
сканирования, `__` &ndash; позиция без клавиши. Только вместо клавиш хоста
стоят имена клавиш машины, и модификаторов `_` и `^` нет: клавиша рисунка
замыкает свой контакт матрицы и больше ничего, а код из него делает ПЗУ.
Пустые строки и комментарии строк матрицы не занимают:

~~~
shift:      key_shift
ctrl:       key_ctrl
rus-line:   key_ruslat

key_space  key_ar2   key_tab    key_ps     key_enter  key_str    key_left   key_right
key_up     key_down  key_home   key_f1     key_f2     key_f3     key_f4     key_f5
...
~~~

Модификаторы сканирующей клавиатуры в матрицу не входят &ndash; у каждого своя
линия (__~shift__, __~ctrl__, __~ruslat__). РУС/ЛАТ здесь не переключатель, а
обычная клавиша: регистр хранит ПЗУ и выводит его на __~ruslat_led__. Поэтому
она объявляется ролью __rus-line__, а не __rus__: пока она нажата на рисунке,
удерживается линия __~ruslat__, и ПЗУ успевает ее опросить. Мгновенное
нажатие-отпускание, которым рисунок переключает защелку __rus__, прошло бы
между двумя опросами незамеченным. Лампа `led_rus` при этом горит по линии
индикатора, то есть по тому, что решила сама машина. Отсюда требование: роль
__rus-line__ имеет смысл только у машины с подключенным __~ruslat_led__, иначе
регистр эмулятора (а с ним и перекладка ЙЦУКЕН для клавиатуры хоста) после
нажатия на рисунке не сменится.

Тело таблицы для __uknc-keyboard__ &ndash; строки `имя: номер`, по одной на
клавишу машины: слева имя клавиши, оно же __id__ элемента рисунка, справа её
номер. Модификаторов нет совсем &ndash; у этой машины регистровые клавиши имеют
собственные номера, и раскладку по ним выбирает ПЗУ, поэтому они объявляются
ролью __hold__ и там же, в теле, получают свой номер (пометки регистра
`+shift`/`-shift` бывают только в раскладке хоста, см. [uknc-keyboard](#uknc-keyboard)):

~~~
hold: key_shift_1
hold: key_ctrl

key_a:          &72
key_shift_1:    &105
key_ctrl:       &46
~~~

Требования к рисунку:

* Кликабельная клавиша &ndash; элемент (обычно группа `<g>`), чей __id__ совпадает с именем клавиши в нативной таблице. Все прочие элементы рисуются, но не реагируют.
* Два имени зарезервированы под лампочки: элемент с __id__ `led_rus` горит в русском регистре, `led_lat` &ndash; в латинском, а негорящий затеняется черным. Лампочка не клавиша: она показывает состояние машины, а не нажатие, и нажать ее нельзя. Если лампочка нарисована, соответствующая клавиша (РУС, ЛАТ либо один переключатель на обе) больше не подсвечивается: регистр показан там, где его показывает сама машина, и только один раз. Рисунок без таких элементов их просто не получает &ndash; так у БК, где регистр виден по клавишам РУС и ЛАТ.
* Имя задается атрибутом __id__, а не подписью: в Inkscape это поле &laquo;ID&raquo; в свойствах объекта (Ctrl+Shift+O), а не &laquo;Метка&raquo;.
* На корне обязателен `viewBox`. Трансформации допустимы и на самих клавишах, и на слоях, в которых они лежат: Inkscape вешает `transform` на слой при первой же его правке.
* Текст надо перевести в кривые: шрифта, которым набран рисунок, на другой машине может не оказаться, а кириллица при подстановке уезжает по метрикам.
* Qt рисует SVG в объеме профиля 1.2 Tiny. Градиенты поддерживаются, а фильтры, размытия, тени, `<use>` и CSS-селекторы в блоке `<style>` &ndash; нет; цвета надо задавать атрибутами или инлайновым `style`.
* В браузере рисунок встраивается в DOM, поэтому он должен быть самодостаточным: без внешних картинок и шрифтов.

### mouse

Мышь с защелкнутыми выходами направлений, как УВК-01 «Марсианка» для БК. У нее
нет счетчиков: каждый шаг шара (0,5 мм) взводит триггер своего направления, и
триггер держится, пока машина не подаст сброс. Кнопки &ndash; простые контакты.
Программа читает линии, сбрасывает их и читает снова, так что скорость курсора
задает она сама: шаг за опрос.

Перемещение мыши хоста (или команды сценария [MOUSE](SCRIPTING.md#mouse))
копится в шагах и выдается по одному, не быстрее, чем шар мог бы их сделать.
Следующий шаг ждет, пока предыдущий не сброшен. Если подключен строб чтения,
триггер, сброшенный до того, как программа его прочитала, возвращает шаг в
очередь, и программа получает все шаги до единого; настоящая мышь такие шаги
теряет (программы нередко сбрасывают линии дважды за опрос), от чего курсор
только отстает от руки.

~~~
mouse : mouse {
	~reset = !port-ppi-out.value[3]
	~read = port-ppi.access
}

port-ppi : port {
	size = _16
	~data[0-7] = mouse.out[0-7]
}
~~~

* Параметры
    * __up__, __right__, __down__, __left__: Биты направлений. По умолчанию 1, 2, 4 и 010, как у «Марсианки» на порту 0177714;
    * __button1__, __button2__: Биты кнопок «Л» и «П». По умолчанию 040 и 0100;
    * __rate__: Наибольшая частота шагов в секунду. По умолчанию 2000 &ndash; скорость 1 м/с при шаге 0,5 мм из руководства по эксплуатации.

* Интерфейсы
    * __~out{16, out}__: Триггеры направлений и нажатые кнопки, взведенный &ndash; единица;
    * __~reset{1, in}__: Сброс триггеров, пока линия в единице. Неподключенная линия мышь не сбрасывает;
    * __~read{1, in}__: Строб чтения линий машиной, необязательный.

__Свойства для сценариев__: __state__ &ndash; значение выхода, __pending__ &ndash;
шагов, которые программа еще не забрала, по обеим осям вместе, __plugged__
&ndash; подключена ли мышь.

Протокол взят из тестовой программы руководства по эксплуатации УВК-01: она
читает порт 0177714, пишет в него 0 и 010 и рисует курсор кодами 031-037 по
битам направлений; кнопки 040 и 0100, нажатые вместе, завершают программу.

### connector

Разъем, в который включено одно из нескольких устройств ввода или ни одного.
Джойстик и мышь БК занимают одни и те же линии порта 0177714, поэтому оба
описаны в конфигурации, а разъем решает, какое из них подключено. Выключенное
устройство не получает событий хоста и не выставляет свой выход.

Так же выбирается звуковая приставка БК: [ay8910](#ay8910) и [covox](#covox)
принимают запись в один порт 0177714. Вынутая приставка записей не принимает
и звука не дает.

Единственный параметр устройства (выпадающий список на панели инструментов)
выбирает подключенное устройство; выбор запоминается для каждой конфигурации,
как и остальные параметры устройств. Машина без разъема работает как раньше:
джойстик и мышь в ней всегда подключены.

~~~
up : connector {
	devices = joystick|mouse
	default = none
	icon = joystick.png
}
~~~

* Параметры
    * __devices*__: Устройства, разделенные символом "|": [joystick](#joystick), [mouse](#mouse), [ay8910](#ay8910), [covox](#covox);
    * __default__: Имя устройства, подключенного до выбора пользователя, или __none__. По умолчанию __none__;
    * __kind__ (input/sound): Назначение разъема, от которого зависит только подпись списка на панели: __input__ (по умолчанию) &ndash; «Устройство ввода», __sound__ &ndash; «Звук»;
    * __label__: Собственная подпись разъема вместо подписи по __kind__. Она же &ndash; подсказка у значка на панели инструментов и название строки в [редакторе расширений](#редактор-расширений). Берется из конфигурации как есть, без перевода, и нужна машине с несколькими разъемами: у УК-НЦ `label = LPT Sound` отличает приставку на принтерном порту от звукового модуля;
    * __icon__: Картинка слева от списка на панели инструментов. Ищется так же, как остальные файлы машины: рядом с конфигурацией, в ее подкаталоге __files__, в каталоге __data__. Без параметра (или если файл не найден) рисуется значок настроек.

__Свойства для сценариев__: __device__ &ndash; имя подключенного устройства или
__none__. Команда __plug(имя)__ подключает устройство, __plug(none)__ освобождает
разъем.

~~~
COMMAND up.plug(mouse)
~~~

### taperecorder

Магнитофон

~~~
tape : taperecorder {
	baudrate = 1200
	encoding = msx
	files = "Orion-128 tape files (*.rko)"
	~input  = port-keyboard.CL[0]
	~output = port-keyboard.CH[4]
}
~~~

* Параметры
    * __baudrate__: Скорость работы по умолчанию. По умолчанию &ndash; 1200.
    * __encoding__: Формат кодирования данных на ленте. Значения: _msx_, _rk86_, _bk_, _uknc_. По умолчанию &ndash; _msx_.
    * __files__: Фильтр для окна открытия файла. Если не указан, то значение берется из раздела __system__.
* Интерфейсы
    * __~input{1, in}__: Подключение входа.
    * __~output{1, out}__: Подключение выхода.
    * __~speaker{1, out}__: Подключение к динамику для воспроизведения звука ленты.

__Примечания__:

* Кодирование _rk86_ повторяет сигнал Монитора Радио-86РК и поддерживает как чтение, так и запись.
  Бит занимает два полупериода, первый несет его инверсию, второй сам бит, так что в середине ячейки
  фронт есть всегда, а на границе &ndash; только между двумя одинаковыми битами. Записанным файлом
  становится все, что идет после первого байта синхронизации $E6, то есть ровно содержимое
  _*.rk_, _*.rkm_, _*.rka_. Имени на такой ленте нет, поэтому расширение для сохранения
  берется из первой маски параметра __files__.
* Байт синхронизации попадает в записанный файл или нет в зависимости от формата: все, что запись
  в __[TapeFiles]__ перечисляет перед __data__, добавляется при воспроизведении и в файле не лежит.
  У _*.rk_ там стоит __$E6:1__, и запись его отбрасывает; у _*.rko_, который несет собственную
  преамбулу и собственный $E6, не стоит ничего, и запись его сохраняет. Поэтому у магнитофона
  машины, пишущей _*.rko_, параметр __files__ должен называть именно это расширение.
* Кодирование _bk_ повторяет сигнал Монитора БК и поддерживает как чтение, так и запись. Остановка записи предлагает сохранить снятое, причем имя и расширение берутся из того, что удалось распознать в сигнале: текст БЕЙСИКа &ndash; как _*.asc_, остальное &ndash; как _*.bin_ с заголовком адреса загрузки.
* Кодирование _uknc_ повторяет сигнал драйвера магнитофона в ПЗУ УК-НЦ и поддерживает как чтение, так и запись.
  Выход переключается из прерывания таймера, поэтому сигнал &ndash; полупериоды двух длин: бит 0 это один
  длинный период, бит 1 &ndash; два коротких, оба по 832 мкс (1200 бод). Байт &ndash; бит 0, восемь битов младшим
  вперёд и два бита 1. Файл с заголовком идёт так: пилот-тон 8000 битов, блок имени (8 слов), длина в
  словах и адрес, пилот-тон 2000 битов, данные и контрольная сумма. Файл _*.uknc.tap_ хранит последовательность
  таких файлов без сигнала и без контрольной суммы: 16 байтов имени, длина, адрес, данные. Контрольная сумма
  считается при воспроизведении, и ПЗУ её проверяет, поэтому испорченная запись не читается. Запись в __[TapeFiles]__ ищется по последнему расширению, поэтому для таких файлов она называется __uknc.tap__.
* В секции __[TapeFiles]__ ini-файла формат можно задать отдельно для машины записью вида __&lt;тип системы&gt;.&lt;расширение&gt;__ &ndash; она имеет приоритет над общей записью для того же расширения.
* Формат воспроизведения задается первым полем записи в __[TapeFiles]__ и не обязан совпадать с __encoding__: значение _bk-ascii_ пишет на ленту программу БЕЙСИКа в текстовом виде. БЕЙСИК разрезает такую программу на части по 256 байт, каждую пишет отдельным файлом с именем вида `ИМЯ  .ASC #000` и закрывает последовательность файлом без номера, поэтому одним файлом текст записать нельзя: LOAD прочитает первую часть и будет ждать продолжения.

### dl11

Последовательный порт DEC DL11: приёмник и передатчик, у каждого своя готовность, разрешение прерывания и вектор. У УК-НЦ так устроены стык С2 (176570-176576) и сетевой адаптер СА (176560-176566). Линия выходит на последовательный порт хоста &ndash; настоящий или виртуальный (пара com0com на Windows, `socat` на Linux), к которому подключается, например, сервер HX [OpenHX](https://github.com/anpp/openhxserver) или терминальная программа.

~~~
c2 : dl11 {
	baud = _9600
	rx_vector = 370
	tx_vector = 374
	port = COM5
	~iako = cpu.iako
}
~~~

| Смещение | Регистр | Чтение | Запись |
|---|---|---|---|
| 0 | RCSR | разряд 7 &ndash; принят байт, 6 &ndash; разрешение прерывания, 12 &ndash; переполнение | только разряд 6 |
| 2 | RBUF | принятый байт; снимает разряды 7 и 12 RCSR | игнорируется |
| 4 | XCSR | разряд 7 &ndash; передатчик свободен, 6 &ndash; разрешение прерывания, 2 &ndash; петля, 0 &ndash; обрыв | разряды 0, 2, 6 |
| 6 | XBUF | 0 | байт на передачу; снимает разряд 7 XCSR |

Байтовая запись в младший байт регистра &ndash; то же, что запись слова; в старший байт ничего не меняет: там нет разрядов, которые пишет программа, а передачу начинает только младший байт XBUF. Байт идёт по линии время десяти посылок (8N1) на скорости __baud__. В петле (разряд 2 XCSR) переданный байт возвращается в собственный приёмник, а линия хоста отключена. Байт с линии принимается, только когда приёмник пуст, поэтому от порта хоста и из сценария переполнения не бывает.

* Параметры
    * __baud__: Скорость линии, бод. По умолчанию 9600.
    * __rx_vector__, __tx_vector__: Векторы прерываний приёмника и передатчика. По умолчанию 060 и 064.
    * __station__: Номер станции сетевого адаптера УК-НЦ, 0-63. Виден в старших разрядах всех регистров: разряды 0-3 номера &ndash; в разрядах 8-11, разряды 4-5 &ndash; в 13-14, мимо разряда 12 (переполнения). Не задан &ndash; разряды нулевые.
    * __rcsr_mask__: Разряды RCSR, которые пишет программа. По умолчанию 0100 (разрешение прерывания), у СА УК-НЦ &ndash; 0104.
    * __xbuf_read__: Байт, который читается из XBUF. По умолчанию 0; у УК-НЦ 0360 у СА и 0370 у С2 &ndash; значение СА проверяет заводской тест.
    * __port__: Порт хоста. На Windows &ndash; `COM5` (открывается как `\\.\COM5`, так работают и COM10 и выше); на Linux и macOS &ndash; путь (`/dev/ttyUSB0`, `/dev/pts/3`), имя без `/` ищется в `/dev`. Если порт не открылся, машина всё равно загружается, поле __connected__ показывает 0. В веб-версии портов нет.

* Интерфейсы
    * __~virq{1, out}__, __~vector{16, out}__: Запрос прерывания процессору (активный ноль) и его вектор.
    * __~virq_in{1, in}__, __~vector_in{16, in}__: Цепочка приоритетов: чужой запрос пропускается к процессору, когда своего нет.
    * __~init{1, in}__: INIT магистрали (выход процессора __~init__): сбрасывает регистры &ndash; приёмник пуст, передатчик свободен, прерывания, петля и обрыв сняты.
    * __~iako{16, in}__: Подтверждение прерывания процессором (вектор). Запрос однократный: он встаёт, когда готовность появляется при разрешённом прерывании (или прерывание разрешают при готовности), и снимается подтверждением со своим вектором либо пропажей условия.

* Команды
    * __connect__ "порт": Выводит линию на порт хоста.
    * __disconnect__: Отключает линию от порта хоста.
    * __send__ "текст": Подаёт байты в приёмник, как будто они пришли по линии; понимает `\n`, `\r`, `\t` и восьмеричные `\ooo`.
    * __sendfile__ "файл": Подаёт в приёмник содержимое файла. Так сценарий играет роль машины на другом конце линии.
    * __plug__ [0|1]: Заглушка на разъёме: выход линии замкнут на вход, порт хоста отключён. Её ждёт заводской тест СА («ЗАГЛ.»).
    * __station__ n: Номер станции (см. параметр __station__).

* Поля для сценариев
    * __rcsr__, __xcsr__: Регистры состояния.
    * __connected__, __port__: Подключена ли линия к порту хоста и к какому.
    * __sent__, __received__, __queued__: Сколько байтов передано, принято и ещё ждёт приёма из команд.
    * __vector__: Вектор, предложенный процессору, или 0.
    * __station__, __plug__: Номер станции (-1 &ndash; не задан) и заглушка.
    * __output__: Последние переданные байты, старые первыми; `output(n)` &ndash; последние n.

### i8251

Программируемый контроллер последовательного интерфейса Intel 8251, КР580ВВ51 (УСАПП). [Документация](https://emuverse.ru/wiki/Intel_8251).

Устройство конфигурируется программно через записываемые в него управляющие слова (mode word, command word), а не через параметры конфигурации.

~~~
usart : i8251 {}
~~~

* Интерфейсы
    * __~address{1, in}__: Адрес внутреннего регистра (A0): 0 &ndash; данные, 1 &ndash; управление/статус.
    * __~data{8, in/out}__: Данные для записи/чтения внутреннего регистра.
    * __~txrdy{1, out}__: Передатчик готов к приему данных.
    * __~rxrdy{1, out}__: Приемник содержит принятые данные.
    * __~txe{1, out}__: Буфер передатчика пуст.
    * __~dtr{1, out}__: Data Terminal Ready.
    * __~rts{1, out}__: Request To Send.
    * __~dsr{1, in}__: Data Set Ready.
    * __~cts{1, in}__: Clear To Send.
    * __~syndet{1, in}__: Обнаружение синхросимвола (синхронный режим).
    * __~txd{8, out}__: Передаваемые данные (побайтная эмуляция).
    * __~rxd{8, in}__: Принимаемые данные (побайтная эмуляция).
    * __~txc{1, in}__: Тактовый вход передатчика.
    * __~rxc{1, in}__: Тактовый вход приемника.
    * __~c{1, in}__: Внешний тактовый вход (альтернатива методу clock()).

### i8253

Трехканальный таймер/счетчик Intel 8253, КР580ВИ53. [Документация](https://emuverse.ru/wiki/%D0%9A%D0%A0580%D0%92%D0%9853)

~~~
timer : i8253 {
	clock = 1/1
	clock0 = 1/2
	clock1 = 1/2
	clock2 = 1/2
}
~~~

* Параметры
    * __clock__: Общая тактовая частота. Может указываться как независимо, так и в долях от системной частоты в формате "множитель/делитель". По умолчанию &ndash; 1/1.
    * __clock0__, __clock1__, __clock2__: Индивидуальные тактовые частоты для каждого канала. Если указаны, переопределяют общий __clock__ для соответствующего канала. Формат аналогичен __clock__.
* Интерфейсы
    * __~address{2, in}__: Адрес внутреннего регистра при записи данных.
    * __~data{8, in/out}__: Данные для записи во внутренний регистр.
    * __~output{3, out}__: Выходные линии счетчиков.
    * __~gate{3, in}__: Входы разрешения счета. Если не подключены, то счет всегда разрешен.

Пример использования в качестве трехканального звукового генератора:

~~~
sound : speaker {
	~mixer[0-2] = timer.output[0-2]
}

mapper : memory-mapper {
	portstomemory = 1
	...
	@memory[$EC00-$ECFF] = timer
}
~~~

### i8255

Контроллер параллельного интерфейса Intel 8255, КР580ВВ55.  [Документация](https://emuverse.ru/wiki/Intel_8255).

~~~
port-user : i8255 {}
~~~

* Параметры
    * __control__: Управляющее слово, с которым микросхема оказывается после сброса. Без него порты стоят на ввод и ждут слова от программы, как настоящая ВВ55. Параметр нужен там, где порт разведён жёстко и слова ему никто не пишет: параллельный порт УК-НЦ всегда выводит порт A (`control = $80`), и без этого ЦАП Covox на его линиях не слышал бы ни одной записи.

mapper : memory-mapper {
	portstomemory = 1
	...
	@memory[$F500-$F5FF] = port-user
}
~~~

### i8257
Контроллер ПДП Intel 8257, КР580ВТ57.  [Документация](https://emuverse.ru/wiki/Intel_8257).

Ведет четыре канала: адрес и счетчик байт, признак конца счета в регистре состояния, режим автозагрузки. Циклы ПДП запрашивает [видеоконтроллер i8275](#i8275): контроллер отдает ему очередной адрес, продвигает регистры канала и по достижении конца счета либо перезагружает канал 2 из канала 3 (автозагрузка), либо запрещает канал (разряд __TC stop__).

Пока канал запрещен разрядом в регистре режима, обращений к памяти нет и такты у процессора не отбираются &ndash; именно так мониторы машин семейства Радио-86РК гасят экран на время работы с лентой.

~~~
dma : i8257 {}
~~~

* Интерфейсы
    * __~address{2, in}__: Адрес внутреннего регистра при записи данных.
    * __~data{8, in/out}__: Данные для записи во внутренний регистр.

* Свойства для сценариев
    * __address__: Адресные регистры четырех каналов.
    * __count__: Регистры счетчика и режима передачи четырех каналов.
    * __mode__: Регистр режима и регистр состояния.

    * __~ir{8, in}__: Входы запросов прерываний IR0-IR7.

### i8275

Видеоконтроллер ПДП Intel 8275, КР580ВГ75. [Документация](https://emuverse.ru/wiki/Intel_8275).

Ведет растр по символьным тактам и выбирает содержимое экрана из памяти через [контроллер ПДП i8257](#i8257), забирая у процессора такты на каждый цикл ПДП. Готовый символьный ряд отдает [дисплею на основе i8275](#i8275-display) в тот момент, когда луч до него доходит, поэтому знакогенератор, курсор и фаза мигания берутся отдельно для каждого ряда.

Устройство, из которого читает ПДП, задается параметром __memory__; контроллер ПДП и номер канала берутся из [дисплея](#i8275-display), где они и описаны.

~~~
vg75 : i8275 {
	memory = ram
	clock = 3/4
}
~~~

* Параметры
    * __memory*__: Устройство, из которого ПДП читает содержимое экрана.
    * __clock__: Символьная частота как отношение к системной. У машин семейства Радио-86РК это __3/4__: процессор и ВГ75 питаются от одного кварца 16 МГц через делители на 9 и на 12.
    * __dma_cycle__: Тактов системной шины на один цикл ПДП. По умолчанию &ndash; 4, как у ВТ57.

Из четырех байтов команды Reset считается полный кадр: знакомест в ряду и тактов гашения строки, рядов в кадре и рядов гашения кадра, строк в ряду. Частота развертки получается из них и символьной частоты, и ее видно свойством __frame_rate__ &ndash; если она не около 50 Гц, неверен параметр __clock__.

Распознаются все восемь команд. Start Display задает длину пачки ПДП (разряды 0-1: 1, 2, 4 или 8 символов) и паузу между пачками (разряды 2-4: 0, 8, 16, 24, 32, 40, 48 или 55 символьных тактов). Stop Display и Reset гасят вывод, Preset Counters переставляет растр в начало кадра, не трогая разрешение вывода.

Статусный регистр читается по нечетному адресу и очищается чтением: __FO__ (разряд 0), __DU__ &ndash; опустошение ПДП (1), __VE__ &ndash; вывод разрешен (2), __IC__ (3), __LP__ (4), __IR__ &ndash; запрос прерывания в конце кадра (5), __IE__ &ndash; прерывание разрешено (6).

* Интерфейсы
    * __~address{2, in}__: Адрес внутреннего регистра при записи данных.
    * __~data{8, in/out}__: Данные для записи во внутренний регистр.
    * __~irq{1, out}__: Запрос прерывания в конце кадра, если оно разрешено командой Enable Interrupt.

* Свойства для сценариев
    * __mode__: Четыре байта параметров команды Reset.
    * __cursor__: Позиция курсора &ndash; знакоместо и ряд.
    * __command__: Последний байт, записанный в командный порт.
    * __geometry__: Знакомест в ряду, рядов, строк в ряду, тактов гашения строки, рядов гашения кадра.
    * __status__: Статусный регистр без очистки.
    * __display__: 1, пока вывод разрешен.
    * __burst__: Длина пачки ПДП и пауза между пачками.
    * __frame_rate__: Частота кадров, которую дает запрограммированный растр.
    * __frames__: Кадров с момента сброса.
    * __dma_bytes__: Циклов ПДП с момента сброса.
    * __row__: Символьный ряд, на котором находится луч.

### wd1793

Контроллер дисковода WD1793, КР1818ВГ93. [Документация](https://emuverse.ru/wiki/FDC_1793).

Должен работать в паре с одним или более устройствами fdd. На данный момент эмулируется большинство основных команд, кроме блочных.

~~~
fdc : wd1793 {
	drives = fdd0|fdd1
	sync = $04
}
~~~

* Параметры
    * __drives*__: Список подключенных устройств fdd.
    * __sync__: Маска битов адреса, при которых обращение к регистру данных ждет готовности контроллера. В контроллере Ириши (КНГМД RTV*001.89) регистры дублируются по адресам 30-33 и 34-37, но при обращении к порту 37 сигнал READY процессору выдается только после появления DRQ или INTRQ. Эмулятор не может остановить процессор, поэтому вместо этого сразу выполняет работу контроллера до момента готовности очередного байта. По умолчанию &ndash; 0 (обращения не ждут).

* Интерфейсы
    * __~address{2, in}__: Адрес внутреннего регистра при записи данных.
    * __~data{8, in/out}__: Данные для записи во внутренний регистр.
    * __~intrq{1, out}__: Выход запроса на прерывание.
    * __~drq{1, out}__: Выход готовности данных.
    * __~hld{1, out}__: Выход HLD (обычно используется для включения мотора дисковода). Активный сигнал &ndash; высокий. Устанавливается командами типа I с флагом h и любой командой чтения или записи, снимается через некоторое время после завершения последней команды.

### joystick

Джойстик, замкнутые контакты которого выставляются битами на выходном
интерфейсе. Какая клавиша хоста замыкает какой контакт, задается во внешнем
файле в формате файлов клавиатурных раскладок: слева имя клавиши из таблицы
[map-keyboard](#map-keyboard), справа &ndash; биты контакта. Устройств может
быть несколько, клавиши получают все; клавиатура машины получает те же
клавиши, как и без джойстика. Если джойстик описан в разъеме
[connector](#connector), клавиши он получает только подключенным.

~~~
joystick : joystick {
	map = bk-joystick.map
}

port-ppi : port {
	size = 16
	~data[0-7] = joystick.out[0-7]
}
~~~

Файл раскладки стандартного джойстика БК (порт 0177714):

~~~
up:	$0001
right:	$0002
down:	$0004
left:	$0008
end:	$0010
home:	$0020
pgup:	$0040
pgdn:	$0080
~~~

* Параметры
    * __map*__: Файл раскладки. Ищется там же, где файлы клавиатурных раскладок.

* Интерфейсы
    * __~out{16, out}__: Биты замкнутых контактов, нажатый &ndash; единица.

__Свойства для сценариев__: __state__ &ndash; текущее значение выхода. Команда
__KEY__ сценариев нажимает клавиши джойстика так же, как клавиатуры.

Раскладки битов у джойстиков БК встречались разные: в файле дана та, что
принята эмулятором БК v4 (вверх 1, вправо 2, вниз 4, влево 010, кнопка A 020,
огонь 040, дополнительный огонь 0100, кнопка B 0200); у BKBTL кнопки занимают
биты 0-3, а направления &ndash; 020 (влево), 040 (вниз), 0100 (вправо),
0200 (вверх). Для игры с другой раскладкой достаточно поправить файл.

### fdd

Дисковод. Должен использоваться совместно с контроллером.

~~~
fdd0 : fdd {
    sides = 2
    tracks = 80
    sectors = 5
    sector_size = 1k
    selector_value = 0
    mode = logical
    files = "Образы дисков Орион-128 (*.odi)|*.odi"
    files_save = "Образы дисков Орион-128 (*.odi)|*.odi"
    image= orion-128/Disk2.ODI
    ~select  = port-fdc.value[0-1]
    ~side    = port-fdc.value[4]
    ~density = port-fdc.value[6]
    ~motor_on = !fdc.hld
}
~~~

* Параметры
    * __sides*__: Количество рабочих сторон (1/2).
    * __tracks*__: Количество дорожек.
    * __sectors*__: Количество секторов.
    * __sector_size*__: Размер сектора.
    * __selector_value*__: Значение интерфейса __~select__ для выбора устройства (0-3).
    * __files*__: Фильтр для окна выбора файлов образов при загрузке.
    * __files_save__: Фильтр для окна сохранения файлов образов. Если не указан, используется значение __files__.
    * __mode__: Режим работы дисковода. Значения: _logical_ (посекторный образ), _mfm_agat_140_ (MFM-кодирование Агат 140 Кб), _mfm_agat_840_ (MFM-кодирование Агат 840 Кб). По умолчанию &ndash; _logical_.
        * В режиме _logical_ образ &ndash; это дамп секторов в порядке дорожка, сторона, сектор. Файл короче объявленной геометрии принимается как дискета с пустым остатком (так, образы БК бывают на 40 и на 80 дорожек), при сохранении пишется полный объем. Расширения _.dsk_, _.gmd_, _.cpm_, _.img_ и _.bkd_ сохраняются как есть.
    * __layout__: Порядок дорожек в посекторном образе. Значения: _cylinders_ (обе стороны каждой дорожки идут подряд: дорожка 0 сторона 0, дорожка 0 сторона 1, дорожка 1 сторона 0, ...), _sides_ (сначала все дорожки стороны 0, затем все дорожки стороны 1 &ndash; так BIOS Ириши нумерует дорожки второй стороны вслед за первой). По умолчанию &ndash; _cylinders_.
        * Порядок можно задать по расширению файла списком через `|`: `layout = cpm:sides|dsk:cylinders`. Элемент без двоеточия задает умолчание для остальных расширений (если его нет &ndash; _cylinders_). Порядок выбирается при каждой загрузке образа (конфигурация, меню, сценарий), а при сохранении под расширением с другим порядком дорожки перекладываются &ndash; так образ Ириши _.dsk_ (дамп по цилиндрам) сохраняется как _.cpm_ (стороны подряд) и обратно. Текущий порядок виден в свойстве __layout__ в сценариях.
    * __image__: Файл образа, загруженный при старте системы.
        * Файл должен находиться в одном из следующих мест:
            * В том же каталоге, что и __.cfg__;
            * В подкаталоге __files__ рядом с .cfg;
            * В подкаталоге __software__, совпадающем с подкаталогом __.cfg__.

* Интерфейсы
    * __~select{2, in}__: Выбор устройства.
    * __~side{1, in}__: Выбор стороны. Активный уровень &ndash; низкий: 1 выбирает сторону 0, 0 &ndash; сторону 1, как на разъеме дисковода. Если контроллер выдает номер стороны прямо, сигнал инвертируется при подключении: `~side = !port38.value[2]`.
    * __~density{1, in}__: Выбор плотности.
    * __~motor_on{1, in}__: Включение мотора. Активный уровень &ndash; низкий.

### bk-display

Дисплейный контроллер БК. Видеопамять читается либо как один бит на точку
(монохромный режим 512x256), либо как два бита на точку (цветной режим 256x256,
четыре цвета). У БК0010 палитра одна, у БК0011М их шестнадцать, и номер
выбирается регистром. На реальной машине монохромный или цветной режим выбирается
переключателем на корпусе, поэтому в эмуляторе он вынесен в выпадающий список на
панели инструментов, а параметр __mode__ задает лишь начальное состояние.

~~~
display : bk-display {
	vram = vram
	scroll = port-scroll
	mode = color
}

display : bk-display {
	vram = ram5
	vram2 = ram6
	scroll = port-scroll
	control = port-palette
	mode = color
}
~~~

* Параметры
    * __vram*__: Устройство ram видеопамяти.
    * __vram2__: Устройство ram второй экранной страницы. Если не указано, страница всегда одна.
    * __control__: Порт регистра управления изображением (у БК0011М &ndash; 0177662 при записи). Разряды 8-11 задают номер палитры, разряд 15 &ndash; номер выводимой экранной страницы. Если не указан, используется палитра 0 и первая страница.
    * __scroll__: Порт регистра управления скроллингом (у БК &ndash; 0177664). Если не указан, изображение не сдвигается.
    * __scroll_base__: Значение регистра скроллинга, соответствующее несдвинутому экрану. По умолчанию &ndash; 216, что в принятой для БК записи есть &amp;000330.
    * __mode__ (color/mono): Начальный режим вывода. По умолчанию &ndash; _color_.
    * __line_bytes__: Число байтов видеопамяти на строку экрана. По умолчанию &ndash; 64.
    * __lines__: Число строк экрана. По умолчанию &ndash; 256.

Смысл регистра скроллинга: значащими являются только младшие 8 бит, они задают
строку видеопамяти, выводимую в верхней строке экрана. Значение __scroll_base__
соответствует несдвинутому изображению, а строка экрана _n_ берется из строки
видеопамяти _(n + значение &minus; scroll_base) mod lines_. ПЗУ БК наращивает
регистр, не ограничивая его разрядность, поэтому старшие биты содержат
накопленный перенос и смысловой нагрузки не несут. Исключение &ndash; разряд 9:
при нулевом значении показывается только верхняя четверть экрана (64 строки),
остальной растр темный. Это режим расширенной памяти (РП) драйвера ТВ: он
сбрасывает разряд и ставит смещение так, чтобы наверху оказалась область
видеопамяти 070000-077777, а остальные 12 КБ отдает программам. Сама адресация
при этом не меняется: какие строки видны, определяет смещение.

Изображение строится по развертке контроллера К1801ВП1-037, как у дисплеев Агата:
кадр из 320 строк по 64 мкс (256 видимых и 64 служебные, 20,48 мс). Каждая
видимая строка рисуется, когда ее проходит луч, с палитрой, экранной страницей и
разрядом 9 регистра скроллинга на этот момент, поэтому смена палитры посреди кадра
видна полосой. Смещение из регистра скроллинга берется один раз за кадр, в начале
служебной строки с номером 23 (считая с 0 от конца видимых). Длина строки
считается от частоты системного генератора.

Интерфейсы:
* __~frame{1, out}__: Кадровый синхроимпульс: 21-я служебная строка, за 43 строки до
  первой видимой (отдельного кадрового выхода у микросхемы нет, плата берет его из
  синхросмеси). У БК0011М это кадровое прерывание (вход __~irq2__ процессора); запрет
  разрядом 14 регистра 0177662 делается снаружи, например через [mux](#mux).

### bk-timer

Программируемый таймер БК. Занимает шесть байт в области ввода-вывода: регистр
уставки (0177706), текущее значение счетчика (0177710) и регистр управления
(0177712).

~~~
timer : bk-timer {
	divider = 128
}

mapper : memory-mapper {
	@memory[$FFC6-$FFCB] = timer
}
~~~

* Параметры
    * __divider__: Число тактов системной частоты на один тик таймера. По умолчанию &ndash; 128, что при 3 МГц дает шаг около 42.9 мкс, а при 4 МГц &ndash; 32 мкс.

* Интерфейсы
    * __~out{1, out}__: Признак перехода счетчика через ноль, для конфигураций, где он заводится на прерывание.

Разряды регистра управления:

| Разряд | Назначение |
| --- | --- |
| 0 | Запрет счета и предустановка счетчика значением уставки |
| 1 | Кольцевой счет: ноль проходится без перезагрузки счетчика и без признака |
| 2 | Разрешение индикации: при переходе через ноль устанавливается разряд 7 |
| 3 | Однократный счет: после перехода через ноль сбрасывается разряд 4 |
| 4 | Разрешение счета |
| 5-6 | Делитель частоты счета: 0 &ndash; 1, 1 &ndash; 16, 2 &ndash; 4, 3 &ndash; 64 |
| 7 | Признак перехода через ноль |

Разряды 8-15 не реализованы и всегда читаются единицами. Счетчик (0177710)
доступен только для чтения. Запись в регистр управления запускает таймер,
загружает счетчик из регистра уставки и сбрасывает делитель. Типовое использование &ndash; отсчет заданного интервала с ожиданием
признака:

~~~
	MOV #1000., @#177706
	MOV #177712, R2
	MOVB #24, (R2)
1:	TSTB (R2)
	BPL 1
~~~

### bk-fdc

Контроллер дисковода БК (КНГМД на К1801ВП1-128). Занимает четыре байта в
области ввода-вывода: регистр состояния и команды (0177130) и регистр данных
(0177132). Контроллер не знает о секторах: он отдает процессору дорожку словами
по 16 разрядов, находит адресные маркеры и считает контрольный код, а поиск
сектора, заголовки и повторы делает дисковый драйвер в ПЗУ (DISK 326 по адресу
0160000). Одно слово проходит под головкой каждые 64 мкс (300 об/мин, 3125 слов
на дорожку), независимо от тактовой частоты процессора.

Тот же контроллер и по тем же адресам стоит в УК-НЦ, только на шине
периферийного процессора, и там он нужен не только для дискет: ПЗУ щупает его
командой `TST @#177132`, и от ответа зависит весь ход загрузки. Не нашлось
контроллера &ndash; ПП передаёт центральному процессору ключ -1, и пультовый
монитор уходит прямо на загрузку из сети, минуя меню ЗАГРУЗКА. А меню рисует
ПП, и вместе с ним чистит экран, так что без КНГМД машина показывает одну
строку на неочищенном чёрном экране.

~~~
fdc : bk-fdc {
	drives = fdd0|fdd1
}

fdd0 : fdd {
	sides = 2
	tracks = 80
	sectors = 10
	sector_size = 512
	selector_value = 0
	image = andos330.img
	~select = fdc.select[0-1]
	~motor_on = fdc.motor_on
}

mapper : memory-mapper {
	@memory[$E000-$EFFF] = disk {mode = r}
	@memory[$FE58-$FE5B] = fdc
}
~~~

* Параметры
    * __drives*__: Список приводов через ___|___, до четырех. Приводы должны иметь 10 секторов по 512 байт; сторону контроллер подключает к ним сам.
    * __word_cycles__: Число тактов системной частоты на одно слово дорожки. По умолчанию вычисляется из частоты процессора: 256 при 4 МГц, 192 при 3 МГц.

* Интерфейсы
    * __~select{2, out}__: Номер выбранного привода.
    * __~side{1, out}__: Сторона, в инверсии, как ожидает [fdd](#fdd). Подключается к приводам автоматически.
    * __~motor_on{1, out}__: Признак включенного двигателя, активный ноль.
    * __~control{16, out}__: Копия последней записанной команды. На БК0010 разряды 2-3 команды выбирают, что стоит в окне 0120000-0157777 (11 &ndash; ПЗУ БЕЙСИКа, 10 &ndash; ничего, иначе &ndash; 16 КБ ОЗУ блока КНГМД), поэтому в конфигурации они заводятся на __~config__ диспетчера памяти.

Разряды регистра команды (запись в 0177130):

| Разряд | Назначение |
| --- | --- |
| 0-3 | Выбор привода 0-3; при нескольких установленных разрядах выбирается младший |
| 4 | Включение двигателя |
| 5 | Сторона (1 &ndash; верхняя) |
| 6 | Направление шага (1 &ndash; к последней дорожке) |
| 7 | Шаг: каждая запись с этим разрядом сдвигает головку на дорожку |
| 8 | «Начало чтения»: поиск адресного маркера начинается, когда разряд сбрасывается после установки |
| 9 | Запись маркера (только в режиме записи) |
| 10 | Прекомпенсация записи, игнорируется |

Разряды регистра состояния (чтение 0177130):

| Разряд | Назначение |
| --- | --- |
| 0 | Дорожка 0 |
| 1 | Готовность: двигатель включен и дискета есть |
| 2 | Защита записи |
| 7 | Требование обмена: прочитано очередное слово или свободен регистр записи |
| 14 | Контрольный код сошелся (при чтении) или записан (при записи) |
| 15 | Индекс |

Чтение регистра данных отдает слово под головкой (старший байт &ndash; первый на
дорожке), сбрасывает разряд 7, выходит из режима записи и отменяет поиск
маркера. Запись в регистр данных переводит контроллер в режим записи; слова
проходят через двухступенчатую очередь, младший байт слова ложится на дорожку
первым. Когда процессор перестает подавать слова, контроллер дописывает
контрольный код и выставляет разряд 14. Дорожка кодируется из секторов образа
при обращении к ней: промежуток 0x4E, синхронизация 12×0x00, маркер
A1 A1 A1 FE, заголовок (дорожка, сторона, сектор, код размера 2), CRC-16-CCITT,
промежуток 22×0x4E, синхронизация, маркер A1 A1 A1 FB, 512 байт данных, CRC.
Записанная дорожка разбирается обратно на секторы при уходе головки, смене
привода, выключении двигателя, выходе из режима записи и сбросе.

__Свойства для сценариев__: __status__, __command__, __drive__, __track__,
__side__, __motor__, __writing__, __busy__, __position__; для отладки &ndash;
__raw(от,до)__ (байты дорожки под головкой), __marker(от,до)__ (признаки
маркеров по словам) и __trace(от,до)__ (кольцо последних обращений к
регистрам, по три значения на запись: вид, значение, позиция головки; виды:
1 &ndash; команда, 2 &ndash; чтение данных, 3 &ndash; запись данных, 4 &ndash;
смена состояния, 5 &ndash; найден маркер, 6 &ndash; проверка CRC).

Поведение контроллера снято с эмулятора [BKBTL](https://github.com/nzeemin/bkbtl)
и сверено с «Руководством системного программиста БК-0011» (п. 1.3.6.1) и с
разбором ПЗУ DISK 326.

### uknc-channels
Каналы обмена между процессорами УК-НЦ.

~~~
channels : uknc-channels {
}

mapper : memory-mapper {
	@memory[177560-177563] = channels
	@memory[177564-177567] = channels[4]
	@memory[176660-176663] = channels[10]
	@memory[176664-176667] = channels[14]
	@memory[176674-176677] = channels[20]
}

ppu-mapper : memory-mapper {
	@memory[177060-177067] = channels[24]
	@memory[177070-177077] = channels[34]
}
~~~

Пять байтовых каналов с квитированием: три от центрального процессора к периферийному и два обратно. Общей памяти в машине нет, и вместе с [indirect-memory](#indirect-memory) это всё, чем процессоры разговаривают. Системное ПО занимает канал 0 под терминал (экраном и клавиатурой владеет ПП), канал 1 под принтер, канал 2 под команды и блочную передачу.

Устройство одно на обе стороны и включается в **оба** диспетчера с разными базами: стороны видят разные регистры по разным адресам. Собственные смещения устройства:

| Смещение | ЦП | Смещение | ПП |
| --- | --- | --- | --- |
| 000 | канал 0, приёмник, состояние | 024 | канал 0, приёмник, данные |
| 002 | канал 0, приёмник, данные | 026 | канал 1, приёмник, данные |
| 004 | канал 0, источник, состояние | 030 | канал 2, приёмник, данные |
| 006 | канал 0, источник, данные | 032 | приёмники, состояние |
| 010 | канал 1, приёмник, состояние | 034 | канал 0, источник, данные |
| 012 | канал 1, приёмник, данные | 036 | канал 1, источник, данные |
| 014 | канал 1, источник, состояние | 042 | источники, состояние |
| 016 | канал 1, источник, данные | | |
| 020 | канал 2, источник, состояние | | |
| 022 | канал 2, источник, данные | | |

Запись в регистр данных отдаёт байт приёмнику, взводит его готовность и занимает источник; чтение забирает байт, снимает готовность приёмника и освобождает источник. Разряд 7 регистра состояния на стороне ЦП &ndash; готовность (только чтение), разряд 6 &ndash; разрешение прерывания. Периферийный процессор видит все свои каналы в одном регистре: разряды 5, 4, 3 &ndash; готовность каналов 2, 1, 0, разряды 2, 1, 0 &ndash; их разрешения прерываний.

* Параметры
    * __cpu_rx_vector0__, __cpu_rx_vector1__: Векторы приёмников ЦП. По умолчанию 060 и 0460.
    * __cpu_tx_vector0..2__: Векторы источников ЦП. По умолчанию 064, 0464, 0474.
    * __ppu_rx_vector0..2__: Векторы приёмников ПП. По умолчанию 0320, 0330, 0340.
    * __ppu_tx_vector0__, __ppu_tx_vector1__: Векторы источников ПП. По умолчанию 0324 и 0334.

* Интерфейсы
    * __~cpu_virq{1, out}__, __~cpu_vector{16, out}__: Запрос прерывания центральному процессору и вектор к нему. Линия запроса активна нулём, как всё на магистрали 1801.
    * __~ppu_virq{1, out}__, __~ppu_vector{16, out}__: То же для периферийного.
    * __~cpu_iako{16, in}__, __~ppu_iako{16, in}__: Подтверждение прерывания от процессоров, их выход __~iako__. Обязательны: без них запрос канала, однажды выставленный, не снимается.

Если прерываний ждут сразу несколько каналов, выставляется вектор младшего из них, приёмники раньше источников; остальные ждут своей очереди.

Запрос прерывания канала **однократный**, как в UKNCBTL: он выставляется на переходе &ndash; готовность стала единицей при разрешённом прерывании, или разрешение включилось при готовности и взводе &ndash; и снимается, когда процессор его взял (подтверждение с этим вектором), когда байт забран или разрешение выключено. Взвод возвращается пересылкой байта. По уровню «готов и разрешено» делать нельзя: свободный передатчик ПП с разрешённым прерыванием стоит так часами, и, предложенный заново после любого чужого прерывания, он запускает обработчик 175540, а тот в меню ЗАГРУЗКА забирает символ из буфера клавиатуры в никуда &ndash; так терялся ESC стрелки, и меню пропускало каждое пятое нажатие.

* Поля для сценариев
    * __channels__: Состояние всех пяти каналов: данные и обе пары флагов.
    * __sent_c2p__, __sent_p2c__: Сколько байт передано в каждую сторону.
    * __trace__: Последние байты терминального канала 0 от ЦП к ПП, старые первыми; `trace(n)` &ndash; последние n. То, что программа выводит на экран, вместе с управляющими и графическими последовательностями.
    * __cpu_vector__, __ppu_vector__: Вектор, выставленный сейчас каждой стороне, или 0.

### uknc-display
Дисплейный контроллер УК-НЦ.

~~~
display : uknc-display {
	plane0 = plane0
	plane1 = plane1
	plane2 = plane2
	clock_source = ppu
}
~~~

Экран 640x288 точек, 288 видимых строк растра из 312. Контроллер на стороне периферийного процессора, поэтому тактуется от него: __clock_source = ppu__.

* __~frame{1, out}__: Кадровый импульс 1-0 в начале каждого кадра (312 строк по 64 мкс, 50,08 Гц). От него у УК-НЦ идёт прерывание EVNT (вектор 100) обоих процессоров, поэтому оно не расходится с лучом.

**Точка &ndash; три бита, по одному из каждого плана**, считанных по одному и тому же адресу: план 0 даёт младший разряд цвета, план 2 &ndash; старший. Разряд 0 байта &ndash; самая левая точка октета. Три байта дают восемь точек.

**Таблица строк.** Контроллер обходит связный список построчных дескрипторов в плане 0 с адреса `0000270`, по одному дескриптору на строку растра, 307 за кадр; первые 19 приходятся на гашение над картинкой. Дескриптор бывает двухсловным (`[адрес точек][связь]`) и четырёхсловным (`[слово1][слово2][адрес точек][связь]`); первый дескриптор кадра всегда двухсловный.

Разряды слова связи:

| Разряд | Назначение |
| --- | --- |
| 15-2 | адрес следующего дескриптора; маскируется `&~3` для двухсловного, `&~7` для четырёхсловного |
| 2 | тип следующего четырёхсловного: 1 &ndash; палитра, 0 &ndash; параметры |
| 1 | следующий дескриптор четырёхсловный |
| 0 | **переключает** признак курсора &ndash; это не уровень, а триггер |

Четырёхсловный дескриптор палитры: восемь цветов по четыре разряда YRGB, цвет 0 в младшей тетраде первого слова, цвет 7 в старшей тетраде второго.

Четырёхсловный дескриптор параметров:

| Поле | Назначение |
| --- | --- |
| слово 2, разряды 4-5 | показатель растяжки: 0/1/2/3 &ndash; 1/2/4/8 экранных точек на точку (640/320/160/80 в строке) |
| слово 2, разряды 0-2 | яркость, активный уровень нулевой: сброшенный разряд гасит канал (разряд 0 &ndash; синий, 1 &ndash; зелёный, 2 &ndash; красный) |
| слово 1, разряды 0-3 | цвет курсора, YRGB |
| слово 1, разряд 4 | тип курсора: 1 &ndash; графический (одна точка), 0 &ndash; символьный (весь октет) |
| слово 1, разряды 5-7 | номер точки в октете для графического курсора |
| слово 1, разряды 8-15 | позиция курсора, сдвигается вправо на показатель растяжки |

Таблица обходится **по строке за строку, как это делает аппаратура**, а не целиком в начале кадра: программа, переписывающая таблицу посреди кадра, видна ровно так, как её увидел луч.

* Параметры
    * __plane0*__, __plane1*__, __plane2*__: Устройства ОЗУ трёх планов.
    * __colors__ (rgb/grb/gray): Порядок цветовых выходов. У части машин красный и зелёный переставлены (__grb__); __gray__ даёт восемь градаций серого. По умолчанию &ndash; __rgb__. Переключается и с панели инструментов.

* Поля для сценариев
    * __palette__: Восемь цветов текущей строки, по тетраде YRGB.
    * __scale__, __scales__: Растяжка текущей строки и каждой строки последнего кадра.
    * __cursor__: Состояние курсора, как его оставила таблица.
    * __entries__: Сколько дескрипторов обойдено за последний законченный кадр (у исправной таблицы &ndash; 307).
    * __frames__: Сколько кадров начато с пуска машины.
    * __list__: Таблица строк так, как её читает контроллер &ndash; первое, на что стоит смотреть, когда картинка неверная.

### uknc-graphics
Графический блок УК-НЦ: рисование октетами. Регистры 177010-177014 перед ним &ndash; косвенный доступ к планам, это [indirect-memory](#indirect-memory) (`pp-indirect`); рисует блок по его регистру адреса.

~~~
pp-video : uknc-graphics {
	plane0 = plane0
	plane1 = plane1
	plane2 = plane2
	~address = pp-indirect.address
}

ppu-mapper : memory-mapper {
	@memory[177010-177015] = pp-indirect
	@memory[177016-177027] = pp-video
}
~~~

| Адрес | Регистр | Поведение |
| --- | --- | --- |
| 177010 | адрес планов | (pp-indirect) запись сюда **сразу читает** три плана в 177012 и 177014 |
| 177012 | данные плана 0 | (pp-indirect) запись кладёт байт в план 0 по текущему адресу |
| 177014 | данные планов 1 и 2 | (pp-indirect) младший байт в план 1, старший в план 2 |
| 177016 | код цвета точки | три разряда, по одному на план &ndash; цвет установленной точки |
| 177020 | цвет фона, точки 1-4 | четыре триады по три разряда, точка 0 в разрядах 0-2 |
| 177022 | цвет фона, точки 5-8 | то же для точек 4-7 |
| 177024 | октет точки | **чтение** загружает фон из памяти, **запись** рисует восемь точек |
| 177026 | маска | разряд запрещает запись в свой план |

Запись в 177024 &ndash; основная операция рисования: каждый установленный разряд октета берёт цвет из 177016, каждый сброшенный оставляет фон из 177020/177022, и три байта планов уходят в память разом. Восемь точек любого из восьми цветов за одно обращение к магистрали. Именно так ПЗУ машины выводит весь текст.

Регистры данных &ndash; защёлка: повторное чтение память не перечитывает, для свежего слова адрес пишется заново. Через них же периферийный процессор достаёт память центрального (планы 1 и 2).

* Параметры
    * __plane0*__, __plane1*__, __plane2*__: Устройства ОЗУ трёх планов.

* Интерфейсы
    * __~address{16, in}__: Адрес планов &ndash; выход __address__ регистра 177010 (pp-indirect).

* Поля для сценариев
    * __address__, __color__, __background__, __mask__: Содержимое соответствующих регистров.
    * __draws__: Сколько октетов нарисовано с пуска машины.
    * __octet__: Последний октет, записанный в 177024.

### uknc-hdd
Контроллер винчестера УК-НЦ: плата ИДЕ в кассете ПЗУ периферийного процессора.

~~~
hdd : uknc-hdd {
	clock_source = ppu
	image = hdd.img
	files = "Образы винчестера УК-НЦ (*.img *.hdd);;Все файлы (*.*)"
}

ppu-mapper : memory-mapper {
	// Разряды 1-3 регистра 177054: кассета 1, любой из трёх банков
	@memory[2:16][110000-117777] = hdd
	@memory[4:16][110000-117777] = hdd
	@memory[6:16][110000-117777] = hdd
}
~~~

Плата занимает верхнюю половину окна кассеты, 110000-117777; нижняя, 100000-107777, остаётся за её собственным ПЗУ, которое и умеет с накопителем работать. Регистр выбирается разрядами 1-3 адреса **в обратном коде**:

| Адрес | Регистр |
| --- | --- |
| 110000 | состояние (чтение) и команда (запись) |
| 110002 | номер головки и накопителя |
| 110004 | старший байт цилиндра |
| 110006 | младший байт цилиндра |
| 110010 | номер сектора, считая с единицы |
| 110012 | число секторов |
| 110014 | ошибка |
| 110016 | данные |

Данные на магистрали 1801 идут в обратном коде, и плата их не переворачивает: регистры машина читает и пишет дополнением, а сектор приходит так, как он лежит в накопителе. Поэтому дамп такого винчестера, снятый на обычной машине, оказывается инвертированным; образ с признаком inv эмулятор переворачивает обратно, определяя его сам по первому сектору &ndash; так же, как UKNCBTL.

Геометрия берётся оттуда же: байт 0 первого сектора &ndash; число секторов на дорожке, байт 1 &ndash; число головок, число цилиндров считается по размеру файла (так размечают диск программы WD и ID). Поддержаны команды чтения (20, 21), записи (30, 31), объявления геометрии (91) и паспорта накопителя (EC).

**Два способа адресации**, и выбирает его сама программа разрядом 6 регистра 110002:

| Разряд 6 | Адрес |
| --- | --- |
| 0 | цилиндр (110004 и 110006), головка (младшая тетрада 110002) и сектор (110010), сектора нумеруются с единицы |
| 1 | линейный номер в 28 разрядов: 110010 &ndash; разряды 0-7, 110006 &ndash; 8-15, 110004 &ndash; 16-23, младшая тетрада 110002 &ndash; 24-27 |

Это не украшение: драйвер приезжает вместе с диском, а в ПЗУ платы лежит только загрузчик, поэтому на одной и той же плате один образ работает по цилиндрам, а другой линейно.

Образ открывается **на запись**: машина пишет прямо в файл, как настоящая в свой диск. Его отсутствие не ошибка &ndash; гнездо просто пустое, и на обращения к регистрам никто не отвечает; образ вставляют командой __load__. Так и сделано в поставке: файл на сотни мегабайт с эмулятором не возится.

* Параметры
    * __image__: Образ винчестера. Ищется обычным порядком; ненайденный оставляет гнездо пустым.
    * __files__: Фильтр диалога открытия файла.
    * __write_protect__: 1 запрещает запись в образ. По умолчанию 0.
    * __volatile__: 1 &ndash; запись в память: записанные сектора остаются в эмуляторе и читаются оттуда, а файл образа не меняется (годится и файл только для чтения). По умолчанию 0.
    * __sector_time__, __seek_time__: Сколько микросекунд накопитель тратит на сектор и на поиск дорожки перед первым сектором. По умолчанию 256 и 1000 &ndash; примерно как у винчестера тех лет (оборот 16,7 мс, 63 сектора на дорожке). Драйверы ждут разряда «буфер готов» со своими выдержками, и слишком медленный накопитель они считают неисправным.

* Поля для сценариев
    * __attached__, __file__, __inverted__, __protected__: Вставлен ли образ, его имя, снят ли он в обратном коде и запрещена ли запись.
    * __volatile__: 1, когда запись идёт в память, а не в файл.
    * __lba__: 1, когда адрес задан линейно, а не цилиндром, головкой и сектором.
    * __geometry__, __cylinders__, __heads__, __sectors__: Геометрия образа.
    * __status__, __error__, __command__: Регистры накопителя в прямом коде &ndash; такими, какими их видит плата, а не машина.
    * __cylinder__, __head__, __sector__: Текущий адрес.
    * __reads__, __writes__: Сколько секторов прочитано и записано с пуска машины.

* Команды
    * __load__ "файл": Вставляет образ.
    * __eject__: Вынимает образ.
    * __protect__ [0|1]: Запрещает или разрешает запись; без параметра переключает.
    * __volatile__ [0|1]: Включает или выключает запись в память; без параметра переключает. Выключение забывает всё записанное, как и смена образа.

### uknc-timer
Программируемый таймер УК-НЦ, регистры 177710-177714 на шине периферийного процессора.

~~~
pp-timer : uknc-timer {
	clock_source = ppu
	~virq_in = channels.ppu_virq
	~vector_in = channels.ppu_vector
}

ppu-mapper : memory-mapper {
	@memory[177710-177711] = pp-timer
	@memory[177712-177713] = pp-timer[2] {mode = w, strict = 1}
	@memory[177714-177715] = pp-timer[4] {mode = r}
}
~~~

Двенадцатиразрядный счётчик на вычитание с периодом 2, 4, 8 или 16 мкс. При обнулении взводит готовность, при разрешении даёт прерывание по вектору 304 и **сразу перезагружается из буферного регистра**: однократного режима у него нет, счёт всегда цикличный.

| Адрес | Регистр | Доступ |
| --- | --- | --- |
| 177710 | состояние | чтение и запись, объявлен байтовым |
| 177712 | буферный (уставка) | только запись; чтение на машине остаётся без ответа, поэтому диапазон объявляется __strict__ |
| 177714 | текущее значение | только чтение; запись игнорируется |

Разряды регистра состояния:

| Разряд | Назначение |
| --- | --- |
| 0 | пуск (1) или останов (0). Переход 0&rarr;1 загружает счётчик из буферного регистра |
| 1-2 | период счёта: 00 &ndash; 2 мкс, 01 &ndash; 4, 10 &ndash; 8, 11 &ndash; 16 |
| 3 | ошибка переполнения: счётчик обнулился, когда разряд 7 ещё не сняли. Только чтение, снимается чтением 177710 |
| 4 | разрешение прерывания по внешнему событию, вектор 310 |
| 5 | готовность внешнего события. Только чтение, снимается чтением 177714. Пока взведён, счёт стоит |
| 6 | разрешение прерывания при обнулении счётчика, вектор 304 |
| 7 | готовность при обнулении счётчика. Только чтение, снимается чтением 177714 |

Пока таймер стоит, записанное в буферный регистр видно и в счётчике &ndash; ПЗУ машины пользуется этим, очищая буфер и проверяя, что обнулился счётчик.

**Про разряд 0.** Прототипная документация машины говорит обратное &ndash; «ЛОГ.0 &ndash; ПУСК, ЛОГ.1 &ndash; СТОП». Верно противоположное: ПЗУ самой машины пишет `CLR @#177710` с комментарием «Остановить программируемый таймер» и `MOV #101,@#177710` с комментарием «Пуск таймера и разрешение прерываний». Единица пускает.

* Параметры
    * __period__: Базовый период счёта в микросекундах. По умолчанию 2, как у машины; разряды 1-2 делят его дальше.
    * __zero_vector__, __event_vector__: Векторы прерываний. По умолчанию 304 и 310.

* Интерфейсы
    * __~virq{1, out}__, __~vector{16, out}__: Запрос прерывания процессору, активен нулём.
    * __~virq_in{1, in}__, __~vector_in{16, in}__: Цепочка приоритетов. Свой запрос таймер выставляет вперёд, чужой пропускает дальше, поэтому на один вход процессора можно навесить несколько источников &ndash; у процессора он один.
    * __~event{1, in}__: Внешнее событие &ndash; у машины это вход с магнитофона. Перепад взводит разряд 5 и останавливает счёт до чтения 177714; счётчик при этом не перезагружается, и в нём остаётся время с прошлого события &ndash; по нему ПЗУ отличает нули от единиц.
    * __~event_enable{1, in}__: Разрешение внешнего события (разряд 2 регистра 177716). Пока на входе 0, перепады не принимаются. Неподключённый вход разрешает.

* Поля для сценариев
    * __state__, __reload__, __counter__: Содержимое трёх регистров.
    * __running__, __period__: Идёт ли счёт и с каким периодом.
    * __zeroes__: Сколько раз счётчик обнулился с пуска машины.
    * __events__: Сколько внешних событий принято с пуска машины.
    * __vector__: Вектор, предложенный процессору сейчас, или 0.

### uknc-sound
Звук УК-НЦ: линия динамика и сетка частот системного регистра 177716 периферийного процессора.

~~~
sound : uknc-sound {
	clock_source = ppu
	~input = pp-sys.value[7-12]
}
~~~

Устроен не так, как динамик БК: у машины не один разряд, а шесть (техническое описание, таблица 32).

| Разряд | Назначение |
| --- | --- |
| 7 | линия звука. Ноль глушит всё; при нулях в 8-12 звук &ndash; это сама смена уровня программой |
| 8 | 60 Гц (точнее 62.5) |
| 9 | 250 Гц |
| 10 | 500 Гц |
| 11 | 1 кГц |
| 12 | 8 кГц |

Все частоты берутся с одного делителя 128 кГц, поэтому вместо 60 Гц выходит 62.5. Несколько включённых частот собираются «по И», и разряд 7 может такую сборку модулировать. Делитель ведётся от тактов процессора, в домене которого стоит устройство, &ndash; отсюда __clock_source = ppu__.

ПЗУ пользуется обоими способами: щелчок клавиши &ndash; это импульс одного разряда 7, а Ctrl-G включает разряды 7 и 8, тон 62.5 Гц на 0.32 с. В листинге ПЗУ он назван 500 Гц, но разряд 8 &ndash; нижняя ступень сетки.

Устройство надо назвать __sound__: по этому имени окно эмулятора управляет громкостью.

* Параметры &ndash; общие для звуковых устройств (__lpf__, __mix__).

* Интерфейсы
    * __~input{6, in}__: разряды 7-12 регистра; разряд 0 интерфейса &ndash; линия, 1-5 &ndash; сетка.

* Поля для сценариев
    * __control__: разряды 7-12, сдвинутые к нулю.
    * __level__: уровень на выходе прямо сейчас, 0 или 1.
    * __grid__: счётчик делителя сетки, 128000 отсчётов в секунду.

### uknc-keyboard
Клавиатура УК-НЦ (МС7007).

~~~
keyboard : uknc-keyboard {
	clock_source = ppu
	map = uknc.map
	keys = uknc.keys
	picture = ms7007_keyboard.svg
	use_remap = 0
	port-value = pp-kbd-code
	vector = 300
	~irq_enable = pp-kbd-state.value[6]
	~read = pp-kbd-code.access
	~virq_in = pp-timer.virq
	~vector_in = pp-timer.vector
}

pp-kbd-state : port {
	size = _16
	mask = 100
	~data[7] = keyboard.ready
}
~~~

Устроена **не так, как у БК**: контроллер отдаёт машине **номер клавиши, а не символ**, и делает это на оба фронта. Перекодировкой занимается ПЗУ машины, которое при старте строит пять таблиц раскладки, поэтому регистровые клавиши (НР, УПР, ГРАФ, АЛФ, ФИКС) &ndash; обычные клавиши со своими номерами, а модификаторов вида __/S__ в файле раскладки нет. По той же причине у машины нет регистра РУС/ЛАТ в понимании эмулятора, и перекладку ЙЦУКЕН надо выключать: `use_remap = 0`.

| Адрес | Регистр |
| --- | --- |
| 177700 | состояние: разряд 6 &ndash; разрешение прерывания (запись), разряд 7 &ndash; готовность (чтение) |
| 177702 | при нажатии &ndash; номер клавиши; при отпускании &ndash; разряд 7 и **только четыре младших разряда** номера. Чтение снимает готовность |

**Код отпускания &ndash; не номер с разрядом 7.** ПЗУ так его и разбирает: обычную клавишу при отпускании ищет в буфере автоповтора по младшей тетраде (`BIC #177760`, адрес 104614), а регистровую сравнивает с ожидаемым кодом &ndash; 205 для НР (номер 105), 206 для УПР и ГРАФ (46, 66), 207 для ФИКС (107). С полным номером буквы и стрелки отпускались как ни в чём не бывало, а НР залипал навсегда.

**Разряд 6 здесь разрешает прерывание, а не запрещает**, в отличие от одноимённого разряда 0177660 у БК: ПЗУ пишет `MOV #100,@#177700` с комментарием «Разрешить прерывания от клавиатуры» и `CLR @#177700`, чтобы их запретить.

Файл раскладки &ndash; строки вида `имя: номер [пометка]`, по одной на клавишу хоста; [нативная таблица](#экранная-клавиатура) устроена так же, только слева стоит имя клавиши машины и пометок нет.

Регистры хоста и машины у знаков расходятся: `'` на хосте набирается без Shift, а на МС7007 это НР и 7; `:` на хосте с Shift, а на МС7007 без НР. Поэтому знак отдаётся номеру своей клавиши с пометкой регистра:

~~~
':              &16   +shift    // НР и 7
colon:          &174  -shift    // : без НР, НР даёт *
~~~

* `+shift` &ndash; на время нажатия клавиатура сама прижимает НР, `-shift` &ndash; отпускает его. Когда отпущен последний помеченный знак, НР возвращается туда, где его держит Shift хоста (или клавиша НР рисунка).
* Без пометки Shift хоста просто прижимает НР &ndash; так у букв переключается регистр.

Так `TYPE` в сценарии и живая клавиатура дают машине одно и то же: `TYPE "\"A\""` уходит кодами 105, 031, 211, 205, 072, 212, 105, 031, 211, 205.

Номера снимаются с ПЗУ самой машины, и прямо они там не лежат. По адресу 105520 начинаются данные для пяти таблиц раскладки, по 0o130 = 88 элементов каждая, а драйвер клавиатуры ищет в них место так:

~~~
индекс = номер - поправка[номер >> 4],   поправка = 5,12,17,24,31,36,43,50  (адрес 105510)
~~~

Отсюда и матрица, и обратный пересчёт: восемь групп по одиннадцать клавиш, младшая тетрада номера идёт от 5 до 17, то есть `индекс = 11 * (номер >> 4) + (номер & 17) - 5`. Номера 45 и 65 матрица имеет, а клавиш на них нет; номер СТОПа &ndash; 4 &ndash; в таблицу не попадает вовсе, его ловит сама п/п прерывания и ставит центральному процессору HALT.

* Параметры
    * __map*__: Файл раскладки клавиатуры хоста.
    * __keys__, __picture__: Нативная таблица клавиш машины и её рисунок, см. [Экранная клавиатура](#экранная-клавиатура).
    * __port-value*__: Порт, в который кладётся номер клавиши (на машине 177702).
    * __vector__: Вектор прерывания. По умолчанию 300.

* Интерфейсы
    * __~ready{1, out}__: Готовность. Уровень, а не импульс: стоит, пока не прочитан регистр кода.
    * __~read{1, in}__: Строб обращения к регистру кода, снимает готовность.
    * __~irq_enable{1, in}__: Разряд разрешения прерывания.
    * __~pressed{1, out}__: Хоть одна клавиша нажата.
    * __~virq{1, out}__, __~vector{16, out}__, __~virq_in{1, in}__, __~vector_in{16, in}__: Запрос процессору и цепочка приоритетов, как у [uknc-timer](#uknc-timer).

* Поля для сценариев
    * __codes__: Сколько кодов отдано машине с пуска.
    * __last__: Последний код; разряд 7 показывает, было это отпускание (тогда в младших разрядах только тетрада номера) или нажатие.
    * __keys__: Сколько клавиш в раскладке хоста.
    * __ids__: Сколько клавиш у самой машины, то есть в нативной таблице.
    * __queued__: Сколько кодов ждут, пока машина прочтёт предыдущий.
    * __dropped__: Сколько кодов не влезло в очередь (в ней 16 мест).

Нажатие не кладётся в регистр сразу, а встаёт в очередь контроллера, и машине коды отдаются из тактов ПП по одному &ndash; следующий только после того, как ПЗУ прочтёт предыдущий. Отсюда __clock_source = ppu__. Очередь нужна дважды. Нажатия окна приходят из потока GUI, а регистр, готовность и линия прерывания ПП живут в потоке эмуляции, и трогать их оттуда нельзя. И код отпускания больше не затирает непрочитанный код нажатия. Для сценария это значит, что код доходит до машины на следующей команде ПП: `LOG keyboard.last` сразу после `KEYDOWN` покажет ещё прежний код.
