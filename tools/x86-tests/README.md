# Тесты ядра 8088

`run8088` прогоняет ядро `i8086core` (`src/emulator/devices/cpu/i8086core.*`,
вариант 8088) по набору [SingleStepTests/8088](https://github.com/SingleStepTests/8088):
сотни тысяч команд, снятых с настоящего кристалла (AMD D8088), с состоянием
регистров и памяти до и после, а также поцикловой записью шины.

Тесты в репозиторий не кладутся (около 0,9 ГБ в сжатом виде).

## Сборка и запуск

~~~
sh build.sh                     # CXX=... если g++ не первый в PATH; MSVC не подходит (dirent.h, popen)
mkdir -p tests && cd tests
curl -sL -O https://raw.githubusercontent.com/SingleStepTests/8088/main/v2/metadata.json
# файлы v2/*.json.gz - по списку из API GitHub или клоном репозитория
cd ..
./run8088 tests tests/metadata.json             # все файлы
./run8088 tests tests/metadata.json F6 F7 -v     # только эти, с первыми ошибками
./run8088 tests tests/metadata.json -n 2000      # по 2000 тестов из файла
~~~

Файлы читаются через `gzip -dc`, так что `gzip` должен быть в PATH (в Git Bash он
есть). Флаги, которые кристалл оставляет неопределенными, маскируются по
`metadata.json`.

## Что сравнивается

* **Результат**: все регистры, флаги (под маской), IP следующей команды, каждый
  байт памяти из `final.ram` и отсутствие записей в другие места. Это должно
  совпадать всегда.
* **Время**: от такта, в котором из очереди взят первый байт команды, до такта,
  в котором взят первый байт следующей, &ndash; так тесты считают `cycles`.
  Печатается доля точных совпадений, среднее расхождение и самые частые
  расхождения (наше минус кристалл).

## Состояние (2026-10-02)

По 2000 тестов из каждого из 323 файлов: результат совпадает в 99,2% случаев.
Все расхождения &ndash; во флагах, которые кристалл кладет в стек при ошибке
деления (DIV, IDIV): микрокод деления успевает изменить их до проверки
переполнения, и без него эти значения не воспроизвести. AAM 0 повторен
отдельно (флаги нулевого результата).

Время совпадает точно примерно в 44% случаев, среднее расхождение &ndash;
2,2 такта. Шина (циклы T1-T4, очередь, подкачка в свободные такты, разделение
слова на два цикла у 8088) моделируется по тактам; внутреннее время команды
взято из таблиц Intel за вычетом циклов шины, поэтому там, где микрокод ведет
себя не по таблице (например, когда исполнительное устройство берет следующий
байт из очереди), появляются расхождения в несколько тактов. Точное время
потребовало бы исполнения по микрокоду, как в MartyPC.
